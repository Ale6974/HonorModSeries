# Honor.Contracts — 봉신계약과 식민지계약

2026-10-24 사용자 답변에 따라 **세력 간 봉신, 영주·인물 간 봉신, 다른 세력 정착지의 식민지계약**을 모두 대상으로 한다. 자치 거점 자동 경영이나 주민 고용계약은 이번 기능의 의미가 아니다.

## 현재 상태

첫 단계는 설계와 엔진 독립 규칙 구현이다. `Source/Honor.Contracts.Rules`와 `Tests/Honor.Contracts.Tests`에 세 계약 범위, 평화 협상과 항복·점령 경위, 고정 조항, 공납 일정·유예, 보호·복무 의무, 피습·포위 방어 요청, 분쟁·귀책·해약, 중복 종속·순환 방지, 자유도시 판정과 성장에 따른 지위 선택, 세력 명예·계약 신뢰·영지 이탈 압박 검사가 있다. 이 코드는 아직 기존 게임 모듈에서 호출하지 않는다.

**Honor.Contracts는 아직 설치하거나 구독할 수 있는 모드가 아니다.** 게임 화면, Scribe 저장, 실물 공납, NPC 협상·보호 퀘스트, 실제 항복·점령 분기와 사건 생성기, 자유도시 표시·선택 편지·설정 화면, 명예·기억 반영, 영·한 플레이어 문구 및 엔진 통합 검사는 미구현이다. 기존 공개 0.2.1 다섯 모드와 ZIP은 그대로다. 새 Workshop 항목이나 모음집 의존성을 추가하지 않았다.

## 플레이 목표

| 계약 | 당사자·범위 | 봉신/식민지 의무 | 종주/영주 의무 |
|---|---|---|---|
| 세력 봉신계약 | 두 세력의 관계 | 합의한 공납, 한도가 있는 복무 | 보호 요청에 응답, 약정한 권리 보장 |
| 개인 봉신계약 | 영주 Pawn과 봉신 Pawn | 지정 임무·복무, 선택 공납 | 보호와 신분 인정, 약정한 대우 |
| 식민지계약 | 종주 세력 ↔ 소속 세력, **지정한 정착지 하나** | 그 정착지의 합의 공납·복무 | 해당 정착지 보호, 지방 통치·외교·추가 징발 제한 준수 |

식민지계약은 한 정착지에만 적용한다. 같은 세력의 다른 정착지까지 자동 종속시키지 않는다. 기본 설계는 Settlement.Faction을 유지하고 계약에 종속 지위를 저장한다. 방문·상업·공격·퀘스트가 계약상 권리를 실제로 따르도록 연결해야 하며, 문구만으로 자치권이 구현됐다고 표시하지 않는다. 완전 병합·플레이어 맵 전환은 별도 기능이다.

개인 봉신의 영주는 Royalty 작위가 없어도 될 수 있다. 귀족 작위에 따른 대우·민감도는 Nobility 연동으로 추가한다. 개인 봉신계약만으로 NPC를 강제 모집하거나 세력을 변경하지 않는다. 초기 협상은 성인·자유인·의사 표현이 가능한 대상에 한정할 계획이며, 결투 예외 허용 설정을 계약 동의 허용으로 재사용하지 않는다.

## 자유도시와 성장에 따른 플레이어 선택

사용자가 정의한 자유도시는 **아무와도 해당 도시에 적용되는 봉건계약을 맺지 않은 도시**다. 우선 새로운 종족/세력 Def 대신 정치적 지위로 취급하며 기존 NPC 정착지에도 같은 판정을 적용한다. 자유도시 전용 세력과 추가 정착지를 생성하는 월드 생성기는 현재 없다.

자유도시는 종주에게 공납·복무할 의무가 없고 그 종주로부터의 계약상 보호도 없다. 일반 동맹·교역·우호 관계는 봉건계약으로 보지 않는다. 독립을 선택한 것만으로 명예 손실, 적대 전환, 무적/안전 보너스를 주지 않는다. 자유도시 또한 공격·포위·항복/점령 계약의 대상이 될 수 있다.

`FreeCityRules`는 현재 활성·분쟁 중인 계약에서 지위를 계산한다. 별도의 영구 자유도시 플래그로 실제 계약을 덮어쓰지 않는다.

- 도시의 소속 세력이 세력 봉신계약의 종속 또는 종주 당사자이면 그 세력의 도시들은 봉건 관계에 속한다.
- 정착지 계약은 지정한 종속 정착지에만 적용하므로 같은 세력의 다른 정착지까지 자동 종속시키지 않는다. 단, 계약에서 종주 의무는 현재 Faction 범위이고 종주 도시 ID가 따로 없으므로 종주 세력은 자유도시 세력으로 취급하지 않는다.
- 주민·영주의 개인 봉신계약은 해당 도시의 지위로 확대하지 않는다.
- 제안만 했거나 한쪽만 서명한 계약은 독립을 없애지 않는다. 유효한 분쟁 계약은 여전히 구속력이 있어 자유도시 선언으로 연체를 지울 수 없다. 만기·합의 해약·파기 후 현재 지위는 장부에서 다시 계산하되 과거 위반 기록과 명예 결과는 지우지 않는다.

플레이어에게는 도시 성장에 따라 **종주 선택 / 자유도시 선언** 결정을 제시한다. 초기 제안 기준은 해당 정착지의 바닐라 기지 가치 **100,000**이며 밸런스 확정값이 아니다. 설정에서 기준을 바꿀 수 있도록 할 계획이다. 규칙 API는 매 관측에 기준값을 받아들이므로 수치가 고정되어 있지 않지만 현재 게임 설정 UI는 없다.

| 단계 | 플레이어에게 제공할 동작 | 규칙 계층의 현재 동작 |
|---|---|---|
| 성장 중 | 기준 미만에서는 일반 독립 정착지로 플레이 | Growing, 선택 강요 없음 |
| 기준 도달 | 도시당 최초 한 번 지위 선택 편지, 나중에 장부에서 다시 열기 가능 | ChoicePending, 시각·당시 가치·기준값 기록 |
| 자유도시 선택 | 봉건계약 없이 독립 유지 | FreeCityChosen, 계약·보상 생성 없음 |
| 종주 후보 선택 | 실제 가능 후보의 조건을 보고 협상 | Negotiating, 후보 선택만으로 서명/공납 시작 안 함 |
| 협상 취소·거절 | 자유도시 또는 다른 후보를 선택 | ChoicePending 복귀, 기준 도달 편지를 다시 발송하지 않음 |
| 실제 계약 발효 | 약정한 의무·보호 적용, 현재 정치 지위 재계산 | FeudalAffiliationRecorded에 선택 경위 기록 |

기준에 처음 도달하면 결정을 보류해도 진행은 가능하도록 한다. 문을 닫은 것만으로 임의 종주를 고르거나 계약을 맺지 않는다. 적격 종주가 없으면 자유도시 선택은 그대로 가능하다. 명예가 낮다고 독립 선택을 막지 않는다. 자유도시가 나중에 자발적으로 종주와 협상하는 것도 허용한다.

발동 대상은 실제로 플레이어 소유인 정착지의 홈 맵이다. 임시 전장·야영지·적 기지·단순 이동체/중력선 홈 판정에 선택 편지를 발송하지 않는다. 여러 플레이어 정착지는 각자의 기지 가치로 관측한다. 이미 해당 범위의 봉건계약이 있으면 모순되는 새 지위 선택을 발송하지 않는다. 맵을 불러올 때 이미 기준을 넘은 도시도 조건을 만족하면 최초 한 번 관측할 계획이다.

가치 조회에는 `map.wealthWatcher.WealthTotal`의 물품·건물·주민 합계를 사용한다. 습격 난이도용 PlayerWealthForStoryteller와 혼용하지 않으며, 계약을 위한 별도 부/평판 화폐를 만들지 않는다. 가치가 떨어지거나 기준 설정을 바꿔도 이미 발생한 선택을 회수하거나 완료한 선택 편지를 다시 띄우지 않는다. 계약 해약 후에는 자동 반복 편지 대신 장부에서 수동으로 재검토할 수 있다.

`CityRecognition`은 선택 경위를 기록하는 엔진 독립 객체다. FeudalAffiliationRecorded나 FreeCityChosen은 현재 외교 지위를 고정하는 플래그가 아니다. 실제 지위는 매번 현재 계약 장부로 계산하고, 활성 계약이 있는 동안에는 오래 열린 선택 화면에서도 자유도시 선언을 거절해야 한다. 원 소유권·홈 맵 조건과 후보의 실제 외교 상태는 게임 어댑터가 클릭/서명 직전에 다시 검증한다. 후보 목록의 표시는 상대의 합의를 뜻하지 않으며 기존 계약 체결·중복 종속 검사를 통과해야 한다.

후속 저장에는 정착지와 소유 세력 참조, 최초 인식 시각·가치·기준, 선택 단계와 협상 후보를 포함한다. 정치 지위 조회 전에 장부의 만기·분쟁 상태를 현재 틱까지 갱신해야 한다. 정착지 상실·파괴·재정착·소속 변경 시 이전 소유자의 선택 기록을 새 도시로 복제하지 않는다. 현재 영·한 편지/장부 UI, 설정, 저장·재로딩, NPC 표시와 세계 생성은 미구현이다.

## 명예가 하는 일

개인 명예는 기존 Core의 Pawn Need를 사용한다. 사용자 추가 요청에 따라 세력 단위의 공적 명예도 기록하며 계약 신뢰와 영지 이탈에 연결한다. 세력 계약은 서명 대표와 책임자를 기록하고 개인 명예·세력 명예와 기존 우호도·소셜 관계, 조항의 부담·상호성으로 수락 여부와 제공 조건을 결정하도록 한다. 평화 협상은 명예 수치만으로 상대의 동의를 강제하지 않는다. 점령 계약은 실제 군사적 지배에 기초한 별도 체결 경위로 구분한다. 모욕 결투의 강제 수락 규칙을 계약 동의로 재사용하지 않는다.

성실한 이행은 책임자에게 명예 사건과 기존 소셜 기억을, 고의 위반은 책임자에게 명예 손실·기억과 필요시 세력 우호도 변화를 준다. Nobility의 개인 민감도는 Core.Change 경로를 통해 적용한다. 수치와 일일/계약별 보상 상한은 아직 확정하지 않았다. 현재 규칙 라이브러리는 세력 명예와 계약 신뢰의 메모리상 수치를 계산하며 실제 개인 Need·관계 기억·우호도에는 연결하지 않았다. 자연 감소로 개인 명예 단계가 내려가지 않는 Core 규칙은 유지한다.

단순 시간 경과, 계약 생성·재서명, 물품 없이 누른 이행 버튼, 같은 영수증 재사용으로 보상을 얻지 못하게 한다. 적의 공격을 받지 않았다고 보호 실패로 판정하지 않는다. 보호 성공은 확인 가능한 임무 결과여야 한다. 계약 수락에 명예를 소모하는 별도 화폐도 만들지 않는다.

## 세력 명예·계약 신뢰·영지 이탈

이번 요청은 이전의 '세력 전체 명예를 별도로 두지 않는다'는 설계를 변경한다. 세력 명예는 검증된 공적 행적을 기록하는 지표이고, 계약 신뢰와 이탈 압박은 해당 계약의 상태다. 이 수치는 구매·소비·이전하지 않는다. 개인 Need의 전체 주민 평균이나 바닐라 세력 우호도 자체를 세력 명예로 사용하지 않는다.

| 데이터 | 범위·현재 구현 |
|---|---|
| 개인 명예 | 기존 Core의 Pawn Need 유지 |
| 세력 명예 | FactionHonorLedger, 내부 0~1·표시 계획 0~100, 사건으로만 변화 |
| 계약 신뢰 | 종속 측→종주, 종주→종속 측 각각의 신뢰 |
| 이탈 압박 | 계약별 0~1 누적, 경고와 대응 기간을 거쳐 이탈 판단 입력 생성 |

공적 사건 후보는 세력 권한으로 체결한 조약 준수·확인된 봉신 구원·약속한 배상과, 고의 조약 파기·보호 거부·수락한 항복 조건 위반이다. 게임 어댑터가 책임 세력·권한·사건 공개 여부·귀책을 확인해야 한다. 개인의 사소한 모욕이나 의도 불명의 패전을 전 세력의 위반으로 처리하지 않는다. 초기 세력 명예 .5는 시험용 중립 제안값이다. 지도자 교체로 같은 세력의 행적을 초기화하지 않을 계획이다.

`RecordVerifiedEvent`는 고유 사건 ID·평가량·적용 시각을 받아 전후 값과 순번을 기록한다. 같은 ID는 다시 소비하지 않는다. 실제 사건 평가와 보상 상한·휴지기·공개/소문 전달은 미구현이다. 임의 새 ID를 반복해 점수를 올리는 행위는 게임 측 증거 검증으로 막아야 하며 현재 라이브러리만으로 검증하지 못한다.

종주의 불명예는 각 직속 영지의 **종주에 대한 신뢰**를 낮춘다. 한 공적 사건을 각 관련 계약에 한 번 적용하고 계약 수만큼 세력 명예를 중복 차감하지 않는다. 종속 세력의 불명예는 종주의 **그 종속 세력에 대한 신뢰**를 낮추며, 그 세력이 자기 하위 봉신의 종주라면 그 직속 계약에도 자기 행적이 반영된다. 상위 종주의 잘못만으로 무관한 하위 세력이나 모든 주민의 개인 명예를 자동 차감하지 않는다. 현재 구현은 세력 봉신·정착지 계약 대상이며 개인 봉신과의 소속/권한 연결은 후속 범위다.

새 계약의 초기 신뢰는 기존 세력 명예에서 시작한다. 시험 정책은 손실 배율 1, 회복 배율 .25로 신뢰 회복을 느리게 한다. 세력 명예가 상한이어도 새로 검증된 이행은 남은 불신을 회복시킬 수 있다. 같은 사건으로 중복 회복하지 않으며, 명예가 회복됐다고 기존 이탈 압박을 즉시 지우지 않는다. 같은 계약의 상태를 로드/갱신 때 새 기본 객체로 초기화해서는 안 된다.

이탈 흐름은 **안정 → 동요 → 경고 필요 → 통보·대응 기간 → 이탈 판단 가능**이다. 낮은 종주 명예와 낮은 신뢰가 심할수록 압박이 빠르게 누적된다. 시험 공식은 일일 증가량 = 기본 속도 × [max(0, (명예 기준−종주 명예)/명예 기준) + max(0, (신뢰 기준−종속 측 신뢰)/신뢰 기준)]이다. 두 조건이 모두 회복되면 압박을 천천히 줄인다. 기준·속도·경고/이탈/회복 문턱·대응 기간은 정책 입력이며 최종 밸런스는 미확정이다.

큰 시간 간격으로 계산해 압박이 이미 높아졌어도 **실제 경고를 전달한 시각부터** 대응 기간을 보장한다. `RecordVerifiedNoticeDelivered`가 있어야 이탈 판단 단계가 열린다. 낮은 회복 문턱까지 안정되면 통보를 해제하고, 새로운 동요에는 새로운 통보와 대응 시간을 둔다. 경고 문턱 근처를 오간다고 편지를 반복 발송하지 않는다. 실제 게임 통보와 저장은 아직 없다.

`SecessionReady`는 이탈 판단 입력이다. 이것만으로 Repudiate를 호출하거나 정착지 소속을 변경하지 않는다. 후속 게임 로직에서 재협상·배상·합의 독립·다른 종주 탐색·독립/반란을 판정한다. 종주의 위반에 따른 정당한 이탈, 자발적 계약의 배신, 강제 점령에서의 독립을 같은 불명예로 처리하지 않는다. 이탈 시 기존 의무·소속·보호 퀘스트도 정리해야 한다. 자유도시는 다른 유효 봉건계약까지 없어야 하며 세력 명예가 낮다고 강제 재가입시키지 않는다. 현재 실제 이탈 AI·독립 사건·소속 변경·무제한 연쇄 이탈 생성은 없다.

게임 어댑터는 세력당 명예 장부와 계약당 안정성 장부를 소유하고 사건을 틱·순번 순으로 전달한 뒤 시간 누적을 수행해야 한다. 오늘의 위반을 어제 기간에 소급 적용하지 않는다. 순번 누락/중복을 거절하므로 누락 사건을 재전달해야 한다. 저장 대상은 세력 명예·사건 ID/순번/시각, 양방향 신뢰·압박·마지막 계산 시각·반영 명예 순번·정책 버전·통보 증거/시각이다. 현재 게임 사건 자동 라우팅·영한 UI·설정·Scribe 저장과 실제 이탈은 미구현이다.

## 협상과 이행 흐름

1. 대상 정착지 또는 인물에서 계약 제안. 세력 계약의 대표·권한과 식민지 대상의 실제 소속을 확인한다.
2. 계약 종류, 기간, 공납 품목·수량·주기·유예, 보호/복무 응답 기한·요청 횟수, 식민지 권리를 양측에 같은 문안으로 제시한다. 실제로 지원하는 조항만 선택 가능하다.
3. 평화 협상과 항복 합의는 양측이 같은 조항에 동의하면 발효한다. 두 번째 서명 시점부터 기간을 계산한다. 한쪽의 재서명으로 기간·조항을 변경하지 않는다. 점령 계약은 아래 별도 절차로 군사 통제 근거를 기록해 발효하며 상대의 서명을 만들어내지 않는다.
4. 계약 장부에서 다음 납기와 미이행 사유, 보호 요청과 해약 조건을 확인한다. 물품 이행은 상단/현장 전달과 검증된 인수 기록으로 연결할 예정이다.
5. 기한을 넘기면 분쟁을 알리고 사유를 확인한다. 배상·유예 재협상, 상호 면제, 합의 해약, 고의 위반 판정을 지원하는 방향이다. 현재 규칙에는 면책과 귀책 파기만 있으며 배상·기한 변경은 없다.
6. 만기 또는 양측 합의 해약은 명예로운 종료다. 일방적 의무 거부나 권리 침해가 확인되면 행위자를 책임 당사자로 기록한다. 양측에 같은 책임 규칙을 적용한다.

예: 종속 정착지가 60일 동안 15일마다 은 100을 보내는 조건을 제안하고, 종주는 기간 내 두 번까지 정해진 보호 임무에 응답한다. 수량·기한은 **설명용 예시이며 기본 밸런스 값이 아니다.** 재난 때문에 공납을 못 보냈다면 즉시 불명예로 처리하지 않고 분쟁에서 사유를 확인한다. 종주가 합의한 보호를 고의로 거부해도 파기 책임이 생긴다.

## 공격·포위·항복·점령으로 계약 생성

사용자의 추가 요구에 따라 군사적 체결 경로를 포함한다. 현재 구현은 엔진 독립 `SettlementConflict` 프로토콜이며 공격 AI나 항복 확률을 실행하지 않는다.

| 경로 | 게임에서 확인해야 할 사실 | 계약 생성·종속 범위 |
|---|---|---|
| 공격 중 항복 | 실제 공격, 권한 있는 수비 측 대표, 양측이 수락한 동일 조건, 생존 정착지 | Capitulation 경위의 정착지 봉신/식민지계약 |
| 포위 중 항복 | 실제 유지 중인 포위, 수비 측 항복 제안과 조건 수락, 생존 정착지 | 같은 항복 합의 경로 |
| 점령 | 수비 패배에 더해 공격자의 현장 통제, 보존된 정착지, 유효한 점령 행정 | Occupation 경위의 강제 정착지 계약 |
| 철수·포위 해제 | 공격/포위가 중단되고 통제를 확보하지 못함 | 새 계약 없음 |
| 약탈·초토화 | 정착지가 폐허가 되어 계약 대상이 사라짐 | 그 폐허에서 새 계약·정기 공납 생성 없음 |

`ContractOrigin`은 Negotiated/Capitulation/Occupation을 기록한다. 점령 계약은 일반 서명 API로 활성화하지 못하며, 확인된 점령 상태에서만 생성한다. 점령 사실과 명령의 증거를 남기고 피점령 측의 동의·서명을 위조하지 않는다. 점령자에게도 보호 조항을 적용한다. 점령 후 양측이 실제 조건에 합의하면 항복 합의 경로로 체결할 수도 있다.

한 지역 수비대의 항복·한 정착지 점령으로 세력 전체나 생존 인물 개인의 충성 맹세를 강제하지 않는다. 이번 코드의 군사 계약은 SettlementCharter에 한정한다. 세력 전체 봉신화는 별도 권한 있는 세력 대표의 강화 협정과 범위 검증이 필요하며 아직 구현하지 않았다. 기존 주군이 있는 대상은 이전 계약을 먼저 처리해야 하고, 전쟁 승리만으로 중복 계약을 덮어쓰지 않는다.

포위는 유지 병력·현장 통제·보급·수비 상태를 실제로 확인하는 기능으로 구현한다. 시간 경과만으로 무료 점령하거나 모든 문명 수준에 박격포 포위 AI를 강제하지 않는다. 항복 수락 전에 정확한 조건과 책임자를 확정하고, 수락 후 공격 중지·수비대 처리·재침공과 약속 위반은 계약/정전 규칙에 연결한다. 점령군 철수·통제 상실·봉기·재점령과 독립 회복은 후속 계약 재검토 사건이며 단순 로드/맵 언로드와 구별해야 한다. 점령 계약에서의 독립 시도에 자동으로 평화 협정 배신과 같은 명예 손실을 주지 않는다.

기존 1.7.4985의 SettlementDefeatUtility.CheckDefeated는 패배 정착지를 DestroyedSettlement로 대체하고 원 정착지를 파괴하며, 마지막 거점이면 세력을 멸망 처리한다. 따라서 **이 처리 전에** 관리 중인 정착지만 대상으로 항복·점령 보존 분기가 필요하다. 모든 정착지의 패배를 막거나 IsDefeated를 전역에서 무조건 false로 바꾸지 않는다. 참여하지 않은 전투는 기본 처리를 유지한다. 패배 판정만으로 공격자 통제를 증명하지 않으며, 폐허 전환·멸망·우호도 보상·편지를 이미 실행한 뒤 단순히 계약만 붙이는 방식도 사용하지 않는다.

또한 바닐라 세력 관계는 세력 쌍에 적용된다. 특정 정착지 종속과 세력 전체의 휴전은 별개다. 원 세력 소속을 유지하는 계약에서 현장 휴전·방문·거래·공격 AI를 어떻게 제한할지 실제 엔진에서 검증해야 한다. 정착지 하나의 항복을 이유로 세력 전체 우호도를 자동으로 최대로 올리지 않는다. 이 로컬 정전/점령 행정 연결은 현재 미구현이다.

## 봉신 피습·포위 사건과 종주의 구원

계약을 맺은 봉신이 제삼자에게 공격·포위당하는 사건을 추가한다. 생성된 월드 사건은 실제 방어 퀘스트와 연결하며 계약별 편지만 보여주고 자동 승리시키지 않는다. 초기에 전 세계 세력이 지속 전쟁하는 시뮬레이션까지 구현한다고 가정하지 않는다.

- **공격받는 봉신:** 대상 정착지·공격 세력·발생 시각을 기록하고 보호 요청을 보낸다. 플레이어는 병력 파견과 현장 방어를 선택한다. 구원 대상의 실제 맵/적/수비대와 승패를 확인한다.
- **포위된 봉신:** 해제 기한과 접근 가능한 구원 목표를 가진 퀘스트로 만든다. 적을 격퇴하거나 확인 가능한 포위 철수를 유도해야 성공이다. 도착하거나 출정 버튼을 누른 것만으로 보호 의무를 이행하지 않는다.
- **결과:** 방어·포위 해제, 구원 실패와 정착지 상실, 적의 자발적 철수, 요청 당시 이미 소멸한 위협, 종주의 고의 거절을 구분한다. 패전만으로 고의 배신이라 단정하지 않고, 기존 분쟁/귀책 규칙과 연결한다. 종주가 직접 봉신을 공격한 경우는 자신을 상대로 하는 구원 요청이 아니라 권리 침해·계약 위반 검토다.

`DefenseCalls.TryOpen`은 현재 검증된 공격/포위 입력을 보호 조항의 의무로 연결한다. 계약 상대·정착지·발생 시각·요청 한도·활성 기간을 확인한다. 식민지계약은 해당 정착지만, 세력 봉신계약은 검증된 그 세력 정착지를 보호 대상으로 삼는다. 개인 봉신 관계만으로 세력의 모든 정착지에 대한 지배권/보호권을 만들지 않는다. 계약 발효 전 공격을 사후에 새 보호 의무로 돌리지 않는다. 기존 전쟁을 인수하는 조항은 별도 동의가 필요한 미구현 기능이다.

한 사건이 공격 단계에서 포위 단계로 바뀌면 같은 사건 ID를 유지한다. 이를 새 사건으로 중복 요청하거나 계약을 옮겨 보상을 반복 지급하지 못하도록 전체 사건 저장소와 거래 기록을 연결해야 한다. 같은 보호 조항의 미해결 요청은 하나로 제한한다. 여러 봉신이 동시에 공격받으면 합의한 한도, 우선순위·대기열·추가 자발적 구원을 UI에 표시해야 하며, 한도 밖 요청을 자동 계약 위반으로 삼지 않는다. 사건 빈도·휴지기·동시 사건 수·난이도 배율을 설정으로 제공할 계획이나 생성기와 설정은 아직 없다.

현재 규칙 코드는 사건을 열 때 의무만 Pending으로 생성하며 성공·명예·물품을 지급하지 않는다. 게임 어댑터는 공격자의 실제 적대성, 대상 소속과 생존, 유효한 위협, 현장 구원 결과를 검증하고 퀘스트와 의무를 함께 저장해야 한다. 맵이 로드되지 않은 동안의 포위·이동 시간·기한과 저장/재개도 별도 시험 대상이다.

## 공통 규칙의 현재 구현

`ContractTerms`는 불변 제안서다. 세력 계약은 Faction 참조 ID 쌍, 개인 계약은 Pawn 참조 ID 쌍만 허용한다. 식민지계약은 정착지 ID와 자치권 스냅샷이 필수다. 자기 자신과의 계약, 음수 물품량, 중복 조항 ID, 무제한 요청을 거절한다. 보호 의무 없는 일방 수탈 계약은 현재 계약 유형에서 허용하지 않는다.

`ContractLedger`는 Proposed → Active/Disputed → Expired/Released/Breached를 관리한다. 분쟁 중에도 이미 합의한 이행은 가능하다. 연체 자체는 귀책을 정하지 않는다. 면책하면 다른 연체가 남았는지 다시 판단하고, 귀책 파기 또는 합의 해약이면 미완료 의무를 정리한다. 최종 상태에서 사건을 다시 호출해도 새 파기나 이행으로 처리하지 않는다.

정기 공납은 발효 시 회차별 ID와 납기를 정한다. 마지막 회차도 원래 유예 기간을 유지한다. 보호·복무는 검증된 사건을 받아 유한한 횟수와 고정 응답 기한으로 생성한다. 같은 조항의 미해결 요청은 중복 생성하지 않는다. 계약 종료 시점 이후 새 요청은 막고, 기간 중 발생한 마지막 요청은 합의된 응답 기한까지 남는다. 요청·인수 증거 ID는 같은 계약 안에서 한 번만 소비한다.

공납은 납기부터 유예 마지막 틱까지 정상 이행이다. 그다음 틱부터 분쟁이며 뒤늦은 인수 기록만으로 과거 위반을 지우지 않는다. 현재는 선납·분할 납부·채무 승계·임의 소급 정산을 지원하지 않는다. 보호/복무는 응답 기한 전 성공할 수 있다.

작업량 방어용으로 계약당 조항 최대 16개, 정기 조항당 최대 120회차, 요청 조항당 최대 120건을 허용한다. 이는 게임 UI 기본 밸런스 값이 아니다. 큰 시간 이동에도 예정 회차를 새 기한으로 덮어쓰지 않으며, 역행 시간과 오버플로 발효를 거절한다.

`BindingRules`는 활성·분쟁 계약을 대상으로 같은 인물/세력의 중복 주군, 직접·간접 순환 종속, 정착지 중복 계약을 막는다. 개인 관계와 세력 관계는 별도 범위다. 하위 봉신 보유는 순환하지 않는 경우 허용한다. 식민지 조약은 그 정착지에만 걸리며 세력 전체의 봉신 관계와 자동 합치지 않는다. 서로 다른 범위의 충돌 권리 조정은 게임 연결 단계에서 별도 검증해야 한다.

장부 클래스만으로 소속·권한·실물 전달이나 증거의 진위를 확인하지 않는다. `RequestVerifiedDuty`와 `RecordVerifiedFulfillment` 입력은 **신뢰할 수 있는 게임 어댑터가 먼저 검증해야 한다.** 이 함수를 단순 버튼에 바로 연결해서는 안 된다. 중복 종속 검사도 두 번째 서명 직전의 실제 전체 장부로 다시 검사해야 한다.

## 저장·자원 처리와 예외

후속 GameComponent에 저장 버전, 고유 계약 ID, 불변 조항, 서명자/책임자, Faction/Pawn/WorldObject의 Scribe 참조, 각 회차 상태·시각·증거·결과 반영 기록을 저장한다. 현재 규칙 객체는 저장 게임에 등록되지 않았고 자동 복구도 구현하지 않았다.

실물 이전은 한 계약 내 증거 중복 검사만으로 충분하지 않다. 전체 계약에 걸친 거래 ID, 실제 물품 소유권 확인, 수량 예약/보관, 전달·인수·결과 반영 단계의 복구 기록이 필요하다. 실패 시 반환/재시도 정책을 두고 한 영수증으로 다른 계약을 갚지 못하게 한다. 실제 자원을 옮긴 뒤 장부만 실패하거나 그 반대가 되는 경우를 엔진 저장·재개 검사로 재현해야 한다.

NPC 정착지의 거래 재고를 곧바로 공납 생산량이나 국고라고 가정하지 않는다. 초기 수령 공납은 실제 확보·인수할 자원으로 한정하고, 별도 생산 모델을 구현할 경우 출처·상한·비용·중단 조건을 명시한다. 무료 정기 은 생성, 저장/재로딩 중복 수령, 회수 가능한 대여 물품 납세를 막아야 한다.

대표 사망·교체, Pawn 월드 이동/구금/의식불명, 세력 멸망, 정착지 파괴·소속 변경, 관계 적대 전환은 재검토·중단·승계 후보 사건이다. 사망자를 즉시 고의 위반자로 삼거나 새 지도자에게 사전 동의 없는 개인 계약을 자동 승계하지 않는다. 세력 계약의 대표 교체와 개인 봉신의 상속은 다른 규칙으로 처리해야 한다. 각 처리 정책은 게임 연결 단계에 명시한다.

## 모듈·DLC·언어 계획

배포될 `Honor.Contracts`는 Core와 1.7용 Harmony를 필수로 하고, 해당 규칙 DLL은 Contracts 배포에만 포함할 계획이다. Core가 Contracts를 참조하지 않는다. 현재 별도 규칙 프로젝트에는 게임 DLL·Core 참조가 없다.

- Society: 증인·가족·숙적과 계약 위반 기억 확장.
- Nobility/Royalty: 실제 작위에 따른 의전·개인 봉신 대우. 기본 계약에는 Royalty를 요구하지 않는다.
- Diplomacy: 유한한 보호/복무 퀘스트 및 합의한 중재 결투 연결.
- Oaths/Ideology: 충성 선서 의식·선택 이념 조항. 기본 계약에는 필요하지 않다.

위 네 모듈은 필수로 만들지 않고 Core API/선택 어댑터로 연결한다. 보호 조항을 표시하려면 Contracts 자체에 검증된 기본 보호 임무가 있어야 하며 Diplomacy 없이 빈 약속만 제공하지 않는다. 결투 중재는 합의 조항에 있을 때만 사용하고 승리했다고 상대의 모든 정착지를 가져오지 않는다.

UI와 사건·편지·Def 설명은 기존 방식대로 영어/한국어 두 언어를 제공한다. 저장 데이터는 번역된 문장 대신 안정적인 ID를 보관하고 불러올 때 현재 게임 언어로 표시한다. 기존 공개 모드의 언어·활성 설정은 이 단계에서 변경하지 않는다.
