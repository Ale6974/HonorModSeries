# Honor.Contracts 연결 흐름 개발 미리보기

## 하위 소실 뒤 상위도 소실된 경우 — 0.3.28 / 1단계

역순 소실은 새 실제 상위 사건이 앞선 **미정리** 하위 범위들을 PriorScopes로 참조하는 별도 경로로 연결했다. 옛 ScopeRoot·Before·사건 ID/순서·파괴/적대 소유권 근거를 바꾸지 않는다. 같은 원래 세력과 동일 미변경 계약/소유권·공통 원 관리 그래프가 확인되어야 하며, 같은 tick의 사건도 이름순으로 추측하지 않는다. 완료한 정리 영수증은 인수하거나 덮어쓰지 않는다. 이는 소실 검토 범위의 통합이며 세력 합병이 아니다.

정리 창은 **현재 가장 높은 소실 범위**만 새 검토 대상으로 제시한다. 이전의 별도 범위·깊은 손실·현재 생존 계약을 모두 포함해 현재 대표와 실제 소유자/소실 상태를 재검사한다. 앞선 범위의 로컬 순서는 그대로 두고 이후의 하위 사건은 새 상위에 별도 순서로 추가한다. 모든 생존 전방 계약을 기존 원자적 재연결로 처리하고 이전 근거마다 자기 결과와 같은 공동 완료 영수증을 보존한다. 오래된 개별 검토나 일부 범위만의 확정은 거절한다. 계층 원본·범위·소유권·완료 영수증이 맞지 않으면 원 자료와 동결을 유지한다.

진행/재진입/중단 중 소실·미기록 과거 소실·후속 재탈환·다른 세력·미지원 집단 의결은 아직 남았다. 주민·재고·native 소속을 변경하거나 보호/군사 의무를 만들지 않는다. Hegemony/WD2의 기존 보류와 모든 pending-operation 가드는 유지한다. 기존 소실 묶음의 추가 통합이므로1단계 잔여 노력35%(7~9묶음) 추정은 유지한다.

## 상위 도시 다음에 하위 도시가 소실된 경우 — 0.3.27 / 1단계

먼저 기록한 상위 도시 소실이 미정리인 동안, 원래의 같은 세력 하위 도시에서 정상 완료한 파괴/적대 소속 상실은 원 범위의 개별 사건으로 저장한다. 각 도시의 고유 ID·원래 계약/Before·실제 원/새 소유자·시각·관측 순서를 유지한다. 고아 하위를 새로 플레이어 영지로 간주하거나 진단 기준선/누락 참조로 소실을 만들지 않는다. 기존 일반 종료 API의 권한은 그대로다.

상위 영지 정리 창에서 **원래 상위 소실**을 선택하면 관련 손실 전체와 살아 있는 전방 계약을 함께 표시한다. 현재 대표와 같은 생존 세력·상위·모든 실제 생존 소유권/옛 소실 상태를 재검토하고 확정한다. 상실한 조상만 건너뛰어 가장 가까운 생존 상위에 연결하며, 새 연결 이력에 건너뛴 종료 계약을 기록한다. 살아 있는 내부 상위·깊은 계약·옛 조건/원 서명·채무는 유지한다. 기록마다 자기 직속 교체 내역을 남기고 모든 손실의 정리 결과를 하나의 장부/archive 교체로 확정한다. 전체가 실제로 소실되어 새 계약이0개인 경우에도 상위/대표가 유효하면 명시적 정리로 동결을 해제할 수 있다.

미정리 범위는 기존 정치/새 물리 작업 동결을 유지하며 자동 재개하지 않는다. 관측 순서/원본/소유권/부분 영수증/후계 연결이 맞지 않으면 원 자료를 유지한다. **하위가 먼저 소실된 뒤 상위가 소실되는 역순 범위 병합**, 재진입·중단·진행 중 이전, 기록되지 않은 과거 소실·후속 재탈환·다른 세력·귀족/연합 의결은 별도 작업이 남아 있다. 주민/물품/실제 도시 소속·개인 서약을 이 정리 작업에서 변경하지 않는다. Hegemony/WD2의 기존 보류를 유지한다.

1단계 잔여 노력은40%에서 약35%(7~9묶음)로 재평가했다. 이는 실제 관측→범위 저장→현재 대표 검토→생존 전체 재연결→원자적 저장을 연결한 부분 진척이며 전체 중첩/중단 복구·합병·독립·승계·미지원 이전의 완료가 아니다.

## 일반 종주의 별도 전쟁 수락 — 0.3.26 / 1단계

소속 창의 기존 전쟁 인수 제안은 이제 연합과 일반 종주 모두에 적용한다. 봉건 편입은 실제 양측 서명이 끝난 활성 플레이어 계약이 먼저 필요하며, 그 계약과 별도로 현재 종주가 전쟁을 수락한다. 현재 NPC 정책은 우호도50 이상, 기존 동맹 보호와 native 외교 권한 유지다. 현재 지도자를 확인하고 전쟁 대상/대표/체제 동의를 원 intent에 남긴 뒤 외교와 직·간접 후손 전체 이전을 진행한다. 이 수락만으로 군사/보호 의무는 생기지 않는다.

연합 평의회/창설 대표와 봉건 지도자는 서로의 권한을 대체하지 않는다. royalTitleTags가 있는 귀족 의결 체제는 별도 절차 전까지 전쟁 인수를 보류한다. 해당 전쟁이 없는 평시에는 기존 일반 가입 흐름을 유지한다. 마지막 native 전쟁 콜백 뒤에도 현재 대표/구성원을 확인한다. 중단한 전쟁 intent는 이미 적대 결과가 모두 기록되었더라도 자동 goodwill hook만으로 외교를 이어 쓰지 않는다. 사용자의 새 검토/복구가 필요하며, 지도자가 바뀌면 새 현재 수락을 원 기록과 별도로 보존한다. 기존 동맹/quest/cap·모든 도시/주민/stock/source-base 가드, 정확한 옛 종주 예외, Hegemony/WD2 보류는 유지한다. 실제 원 계약/채무/내부 하위 계약을 변경하지 않는다.

일반 지도자 경로의 추가 연결이며 1단계 전체 완료나 귀족 의결·합병·정당한 독립·개인 지도자 합류/승계 구현을 뜻하지 않는다. 잔여 노력 추정은1단계40%(7~9묶음)로 유지한다.

## 전시 연합 가입·적대 소유권 상실 — 0.3.25 / 1단계

소속/공유 외교 창에서 **기존 전쟁을 포함한 연합 가입 제안**을 별도로 선택한다. 실제 연합 도시를 기초1표씩 검토하고 과반 수락을 요구한다. 기존 도시가 없는 창설 가입은 현재 대표가 수락한다. 현재 NPC 정책은 기존 도시 연합의 플레이어 관계50 이상(창설 대표는-50 이상), 연합 기존 동맹 보호, 실제 적대/전쟁 범위와 native 변경 권한을 요구한다. 확인되지 않은 규모/기여 보너스는 없다. 이는 가입에 한정한 Honor NPC 정책이며 전체 정치/영향력 의결 완성이 아니다.

원 수락/현재 대표/도시/대상을 먼저 journal에 남긴다. 연합의 실제 NPC 적대 관계를 native 경로로 적용·양측 확인한 뒤 기존 공유 외교와 전체 NPC 후손 이전을 진행한다. 일부 적대 반영 뒤 중단해도 새 선언을 반복하거나 완료로 부르지 않는다. 현재 대표·도시·같은 전쟁 대상의 새 검토를 받아 복구하며 원 동의와 추가 확인/적용 결과를 보존한다. 뒤늦게 화평이 된 확인 대상은 자동 재선포하지 않는다. 후속 다른 소속 변경에도 이전 전쟁 수락 이력을 별도 보관한다. 플레이어 native 소유권과 기존 채무, 도시별 원본/재고/주민/마지막 기지/quest·cap 가드는 유지한다. 다른 적대 출발지를 새로 허용한 것이 아니며 기존 합의 해약한 실제 옛 종주 예외만 유지한다. 일반 봉건 종주 전시 가입은 아직 별도 구현이 필요하다.

정상 완료한 외부 native 소속 변경도 기존에 서로 적대하던 등록 NPC 소유자 사이에서만 관측한다. 원래 계약/실제 owner 이력과 직전 장부가 그대로이고 새 owner/적대가 확인되면 기존 incoming 영지 계약을 TerritoryLost로 종료한다. 상위 도시라면 파괴와 구분한 owner/time/원본 근거를 보관하고, 하위 계약·조건·채무·깊은 하위·주민·물품은 보존한다. 원 세력이 살아 있고 같은 새 소유자가 여전히 확인되는 때 별도로 현재 대표와 하위 재연결을 검토한다. 전투 승리·항복/정복 정당성·독립·새 계약을 자동 생성하지 않는다. 재탈환 때 옛 계약이 부활하지 않는다.

미정리 상위 소실은 다른 계약/소속 변경·초기 구성·새 도시 이전·새 실물 전달을 보류한다. 기존 제안 거절, 실제 별도 소실 관측과 자신의 재연결 검토는 남겨 자체 잠금을 피한다. 현재 Game 객체를 넘은 과거 검토는 집행하지 않는다. 중첩/진행 중 소실·후속 재탈환은 여전히 별도 구현이 필요하다. Hegemony/WD2가 활성화되면 새 전쟁 인수/적대 소유권 관측 경로는 전용 선택형 어댑터 전까지 보류한다. 독립 실행에 새 의존성은 없다.

1단계 전체 잔여 노력은 약40%(7~9묶음) 추정이다. 전체 합병·정당한 일방 독립·지도자 개인 합류/승계·미지원 주민/노예·로딩 맵/복잡 재고·중첩/진행 중 소실 등은 남아 있다.

## 상위 영지 소실 이후 생존 계약 정리 — 0.3.24 / 이전 구현

기존 native WorldObject.Destroy 전후 훅을 확장해 제한된 **플레이어 관리 하위 계층의 상위 NPC 도시** 소실도 기록한다. 동일 도시·실제 소유자·변경되지 않은 장부와 검증된 원래 소속을 확인하고, 정상 반환 뒤 Destroyed=true와 월드 목록 제거를 함께 확인한다. 누락된 참조나 점령·제거만으로 파괴를 추정하지 않는다. 파괴가 진행/중단된 때, 다른 전환/주민/도시 이전·예약 납부가 있을 때 또는 기록 보관이 불가능할 때는 새 집행 권한을 만들지 않는다.

관측 시에는 파괴된 도시의 **들어오는 영지 계약만 TerritoryLost로 종료**한다. 하위 계약은 유지하며 자동 독립/새 종주 서명/Native 소속 변경을 하지 않는다. 실제 계약 화면의 **상위 영지 소실 정리**에서 기록을 고르고 별도 검토/확정한다. 원래 계약/계층 스냅샷과 현재 전체 하위 구조가 같은지, 원래의 상위 주체가 살아 있는지, 모든 생존 도시의 실제 소속이 원래와 동일한 하나의 현재 플레이어 정치 세력인지, 소속 이전 이력과 현재 대표를 확인한다. 기본 경로는 현재 살아 있고 의사결정 가능한 일반 세력 지도자의 새 합의다. 연합의 집단 의결·귀족 의결을 지도자 하나로 대신하지 않는다.

직속 하위 계약은 Replaced로 보존하고 원래의 살아 있는 상위 주체를 liege로 하는 새 계약을 만든다. 고정 가치·주기·유예·운송 조건은 동일하다. 원 서명과 과거 대표/채무/실적을 해약 서명으로 고쳐 쓰지 않으며, 옛 계약과 새 계약을 양방향 연결한다. 새 계약에는 현재 검토한 서명 시각/대표를 사용하고 별도 정리 영수증을 저장한다. 더 아래 계약은 그대로 유지한다. 그 뒤 통상 하위 계약 관리와 향후 별도 소속 이전 검토가 가능하지만 이번 정리 자체는 Native 소유권·주민/의료/포로/노예·재고·개인 맹세를 변경하지 않는다. 이미 같은 실제 세력에 속한 도시는 로딩/주민 유무와 관계없이 이 정치 기록 정리에서 Native 상태를 건드리지 않는다. 이것이 로딩 맵 물리 이전 지원을 의미하지는 않는다.

모든 직속 형제를 한 사본에서 검증한 뒤 장부와 소실/정리 보관소를 함께 교체한다. 보관 용량·계약 개수·계층/소유자·심층 하위 도시 하나가 바뀌어도 부분 적용하지 않는다. 검토 후 장부/대표/실제 세계가 변하면 새 검토가 필요하다. 원래 소실 근거와 각 정리 이력은 새 Scribe 문자열 슬롯에 저장하며 재로드로 자동 정리하지 않는다. 기본 새 nullable 필드는 생략해 이전 JSON을 유지한다. 새 Replaced 기록이 있는 저장을 옛 버전이 이해한다고 가정하지 않는다.

현재 범위 밖: 이미 실제 소속이 다른 생존 도시의 편입, 원래 상위 주체까지 겹쳐 소실된 구조, 하위 구조 변경·진행 중 해약/전환·소실 당시 관련 열린 제안, 점령/재탈환 판정, 상위 도시가 살아 돌아온 객체, 권한 있는 연합/귀족 의결, 개인 지도자 합류·승계, 일반 정당한 독립·전시 가입·전체 합병. 원래 파괴된 도시 계약은 정리 후에도 종료 상태로 남으며 재탈환으로 자동 부활하지 않는다. 부족한 근거를 진단 기준 기록이나 나중의 참조 부재로 대체하지 않는다.

## 실제 납부 실적·기한 알림·최종 동의 이력 — 0.3.23

실제 계약 목록의 공납 계정에 **이 계약의 실적**과 **같은 당사자 간 전체 실적**을 표시한다. 오직 사용자가 실물 납부를 활성화한 실제 계정과 저장된 영수증을 읽는다. 미활성 개발 기록은 이행/실패로 채우지 않고, 미래 회차를 기한 도래/미납으로 계산하지 않는다. 기한과 유예를 포함해 완료한 납부·지연 납부·아직 유예 중·미납 연체·전달 확인 대기를 구분한다. 초과 납부가 실적을 100% 이상 만들지 않도록 이행 가치는 약정 필요액까지만 센다. 미정산 가치는 전달 대기도 포함한다.

같은 liege/subject identity의 이전 계약까지 합산하며 새 계약이나 종주 변경으로 기존 채무/지연 이력을 초기화하지 않는다. 다른 상대의 실적을 직접 점수에 섞지 않는다. 같은 상대에게 실제 공납 연체가 남아 있으면 새 NPC 동의를 보류하고 이유를 표시한다. 실제 물품 납부가 확인되면 미납은 정산되지만 지연 이력은 남으며, 아직 응답 기한 내인 제안은 다시 검토할 수 있다. 이는 NPC의 공개 협상 규칙이며 미납자의 고의/불명예 판정이 아니다. 실적 범위가 기존1200회차 한도를 넘어 완전한 확인이 불가능하면 불완전함을 표시하고 새 동의를 보류한다.

제안 때의 NPC 선서명만으로 나중의 동의를 추정하지 않는다. 최종 서명은 현재 살아 있는 등록된 대표와 조건·우호도·실제 납부 장부·연결된 소유권/위상을 다시 검사한다. 실패하면 원래 제안과 첫 NPC 서명은 그대로 유지한다. 예약된 실물 전달이 남아 있으면 새 제안/최종 서명은 중지한다. 기존 NPC-only 계약 응답을 플레이어용 거절 경로로 바꾸지 않는다.

새 최종 동의는 현재 NPC 세력/대표의 안정ID, 당시 표시 이름, 최종 시각, 원래 NPC 응답 시각과 조건 지문을 별도 저장한다. 계약과 이력의 사본을 모두 검증한 뒤 함께 교체한다. 이름은 당시 표시용이고, ID/조건/서명 시각은 계약 장부와 대조한다. 과거 계약에 없는 대표를 소급 생성하지 않는다. 지도자 사망/개명 뒤에도 역사 기록을 유지하며, 해당 기록으로 새 이전·승계·독립 권한을 만들지 않는다. 새 저장 슬롯의 손상 원본은 유지하고 계약 변경을 차단한다. 기존 계약/공납 JSON 구조와 바이트 형식을 새 필드로 바꾸지 않는다.

**공납 기한 알림 받기** 설정은 저장별로 유지한다. 하루 한 번 검토해 새 미납 연체를 편지 한 장으로 묶으며 상세는 최대10건을 표시한다. 각 회차는 한 번만 기록해 재로드/재시도로 같은 편지를 반복하지 않는다. 전달 확인 대기/납부 완료 회차는 제외한다. 비활성 기간을 날짜별 편지로 소급하지 않고, 다시 켠 뒤 다음 검토부터 현재 상태를 묶는다. 실제 활성화한 기존 채무에 대한 알림일 뿐 개발 기간의 공납을 새로 청구하지 않는다. 알림 보관 한도10000건에 도달하면 기존 기록을 지우지 않고 새 알림만 멈춘다. 알림 자료가 손상되면 원본을 보존하고 알림만 중지하며 실제 납부/계약은 변경하지 않는다.

화면 실적은 짧은 읽기 캐시를 사용하고 실제 새 제안/최종 서명은 캐시 없이 원본을 재검사한다. 공납 장부의 일시적 Revision은 같은 틱의 Prepare/Commit/Cancel/Close에도 캐시를 무효화하며 저장 JSON에 들어가지 않는다. 통지·동의 이력은 물품/환급/원정/명예를 생성하지 않는다. 독립 실행과 향후 선택형 제공자 어댑터 경계는 유지하며 Hegemony/WD2 의존성이나 어댑터는 추가하지 않았다.

## 초기 재편 없이 연합 준비 / 가입 시 기존 적대 보존 — 0.3.22

플레이어 정치 소속 화면에서 **자유도시연합 준비**를 선택하면 기존 공동 연합을 재사용하거나 검증된 기본 생성 경로로 하나를 준비한다. NPC 도시를 배정/생성/이전하지 않는다. 초기 선택이 미정이면 기존 세계 유지로 기록해 다음 로드에서 초기 재편 질문을 반복하지 않는다. 초기 NPC 배치 설정과 플레이어 가입은 분리되며, 새 연합을 준비한 것만으로 가입하거나 공유 외교를 시작하지 않는다. 기존 준비/적용/완료 의도와 전체 NPC 후손 검토·보존·복구를 거쳐 별도로 가입한다.

플레이어 본래 세력과 정착지를 유지하고 기존 계약/채무를 보존한다. 실제 선행 계약이 활성 또는 한쪽만 해약한 상태이면 준비할 수 없다. 예약된 실물 납부/진행 중 정치/도시/지도자 이전·손상 장부 역시 기존 가드에 따라 보류한다. 생성된 연합 ID/참조/초기 선택은 기존 Scribe 슬롯을 사용한다. 새 합병·승계·도시 이전 권한을 부여하지 않는다.

새 가입은 양쪽의 동일 외부 세력 범위를 관측한다. 플레이어가 실제 적대인데 목적지는 중립/동맹이면 공유 외교로 적대를 지우지 않고 보류한다. 음수 우호도만으로 전쟁을 추정하지 않으며 알 수 없는/누락된/중복된 관계를 허용하지 않는다. 연합 가입 화면에 대상 이름과 이유를 표시한다. 동일 검사와 가드는 새 종주 소속 적용에도 적용된다. 목적지의 기존 적대는 기존 별도 공유 외교 검토 화면에 계속 표시한다.

관계 검토 토큰에 목적지뿐 아니라 플레이어의 관측 우호도/종류도 포함해 오래된 확인을 거절한다. 진행 중 의도에서 공유 외교를 쓰기 직전/반복 중 새로 생긴 미검토 적대를 지우려 하면 중지/정지하며, 기존 의도/채무를 지우거나 자동 재개하지 않는다. 전환이 끝난 뒤 정상 외교 동기화의 의미는 바꾸지 않는다. 이는 전쟁 인수의 권한 있는 평의회 수락이나 새 화평 기능이 아니며 해당 일반 전시 가입 경로는 남아 있다.

## NPC에서 오는 종주계약 제안 — 0.3.21

실제 계약 목록에 **NPC 종주계약 제안 받기** 설정을 추가했다(기본 켜짐, 저장별 유지). 첫 검사 기준 7일 후부터 최대 7일마다 1건을 제안하고 같은 세력과는 마지막 제안으로부터 30일 동안 재접촉하지 않는다. 제안은 기존 3일 기한과 동시 후보 8개 상한을 사용한다. 수신 중단 기간은 밀린 제안으로 소급하지 않는다. 미래/잘못된 저장 시각은 원본을 유지하며 자동 제안만 중지한다.

현재 존재하는 인간형 비적대 NPC 세력과 도시·살아 있는 자세력 지도자를 확인한다. 연합/플레이어 관리청은 후보에서 제외하고, 현재 종주·최근 연락·같은 상대의 열린 제안은 제외한다. 아직 연락하지 않았거나 연락이 오래된 세력을 우선하고, 동률이면 우호도와 안정 ID로 정한다. 전환/보존 작업이나 예약된 실물 납부가 있으면 새 제안을 보류한다. 한 후보의 계층 오류나 낡은 binding은 다른 유효 후보를 전부 차단하지 않는다.

제안은 기존 기본 조건(가치100/5일, 유예1일, 배송 공제10%)과 공개된 NPC 응답 정책을 사용한다. 먼저 NPC 서명만 기록하고 편지를 보낸다. 계약 목록에서 조건을 확인한 뒤 별도 플레이어 서명을 해야 발효한다. 기존 종주가 있다면 적법한 해제부터 필요하며 검토/거절만으로 위반·소속 변경·자동 출병을 만들지 않는다. 실제 외교/도시 이전과 실물 납부는 기존 별도 경로다. 실제 보호 의무 집행이 추가된 것은 아니다.

신규 후보 등록/제안/서명은 장부/참조 사본에 준비하고 선택한 상대와 플레이어만 일괄 반영한다. 사용하지 않은 후보나 실패한 제안은 실장부에 등록되지 않는다. 후보 우선순위 규칙은 엔진/외부 모드 독립이며, 나중의 선택형 Hegemony 연동에서 실제 대표/자격 공급원을 바꿀 수 있는 경계다. Hegemony/WD2 의존성·어댑터는 아직 추가하지 않았다.

## 일반 이념을 가진 포로와 이념 알림 안전 검사 (0.3.17)

새 주민 집행 **profile 5**는 역할 없는 일반 이념 신도인 적격 포로를 기존 실제 도시 이전·중단 복구에 연결한다. 원래 세력/포로 신분/신앙·저장 확신도·교리 ID/Def/타입·과거 이념 이력을 결합해 대조한다. 개종·역할 부여·확신도 쓰기는 없으며 이후 신앙 변화도 임의 복구하지 않는다. 관측한 저항도/의지 초기화의 일회 복원, 의료 등급/미시작 표준 수술 원본 보관·복원, 임시 GC 참조 보호와 신선한 동의/외교/재고 검사는 유지한다.

`Pawn.SetFaction`도 먼저 손님 상태 변경을 호출하는데, 기존 이념 검사는 소속 변경 교리 알림만 확인했다. 이제 일반 주민과 포로 모두 이념의 두 알림 전달 함수와 교리별 소속/손님 상태 알림을 확인한다. 손님 상태 알림은 검증된 기본 Precept의 빈 구현만 허용하고 미확인 구현·Harmony 패치·역할 보유자는 차단한다. 기존 profile 1~4와 신앙 증거의 지문/JSON은 바꾸지 않으며 구형 복구는 저장 프로필을 사용한다. 알림 안전 검사는 강화하므로 새로 확인된 위험이 있는 구형 기록도 추측으로 재개하지 않는다. profile 4의 포로는 여전히 이념이 없어야 한다.

기존 단정밀도 JSON 표기는 Framework와 .NET 10에서 다를 수 있다. 진행 중 이전의 증거를 런타임 간 자동 변환하지 않으므로 게임 버전을 바꾸기 전 원래 버전에서 진행 중 이전을 해결해야 한다. 두 버전 각각의 참조 빌드 지원은 진행 중 저장 기록의 상호 호환 보장이 아니다.


## 새 계약 조건 작성 → NPC 응답 → 서명 → 청구 연결 (0.3.20)

실제 계약 제안의 고정값만 사용하던 경로를 바꾸어, 새 계약에서 공납 가치 1~10,000, 주기 1~60일, 유예 0~30일, 봉신 직접 배송 공제율 0~50%를 편집한다. 현재 지원하는 직접 배송만 제안하며 방문 징수·군사/보호 요청 집행을 새로 구현했다고 하지 않는다. 가치는 별도 평판 화폐나 은 개수가 아니라 기존 실제 거래가격 납부의 평가 단위다. 회차별 평가액과 하루 환산 가치를 제출 전에 보여준다. 숫자 입력이 잘못됐거나 소유자/대표가 바뀌었거나 다른 정치 변경이 진행 중이면 제출하지 않는다. 초안 편집/닫기는 장부를 바꾸지 않는다.

초기 NPC 제안 정책은 기존 기본 조건(100/5일/10% 공제)의 하루 평가 가치 18을 기준으로 한다. NPC 종주는 우호도 0 이상, 하루 가치 18 이상, 유예가 납부 주기 이하인 제안을 수락한다. NPC 봉신은 우호도 50 이상, 하루 부담 18 이하인 제안을 수락한다. 기준과 거절 이유를 표시하며, 명예·기여·체제별 교섭을 전부 구현한 것으로 해석하지 않는다. 원래 기본 제안은 이전과 같은 응답 기준을 만족한다. NPC 수락과 플레이어 서명은 별도이며 제출된 조건을 나중에 초안으로 수정할 수 없다.

당사자 등록·제안·NPC 응답을 복사한 장부/바인딩 목록에서 처리한 뒤 성공 시 한 번 교체한다. 소유권/대표/위상/중복 계약 검사 실패로 원래 장부에 고아 정체성이나 일부 서명이 남지 않는다. 정상적인 NPC 거절은 별도의 거절 기록으로 보존한다. 초안을 연 뒤 소유자나 대표자가 바뀌면 새 검토가 필요하며, 실제 서명에서도 현재 당사자 자격을 다시 검사한다.

서명된 공납 가치·주기·유예·운송 비율은 기존 실물 납부 계정과 영수증에 그대로 연결한다. 계정 활성화 시각부터 새 회차를 계산하므로 이전 개발 기간을 소급 청구하지 않는다. 활성 계약·기존 채무/영수증의 조건은 수정하지 않으며, 같은 대상의 기존 활성 계약을 새 제안으로 덮어쓰지 않는다. 계약 목록도 하드코딩된 100/5일 문구 대신 각 기록의 실제 조건을 표시한다. 조건 수정 합의/갱신, 방문 징수·NPC 납부·군사/보호 요청 집행은 별도 후속 작업이다.


### 기존 계약 중의 종주 후보 비교

새 플레이어 봉신 제안은 `ConditionalOffer`로 최대 8개의 서로 다른 종주 후보를 병행할 수 있다. 같은 상대에게 중복 제안은 만들지 않는다. 기존 종주가 있어도 제안과 NPC 응답만 기록하고 현재 장부 소속·외교·공납을 바꾸지 않는다. NPC 응답 전에 플레이어가 서명하거나, 기존 계약이 활성 상태/한쪽 해약 요청 상태일 때 새 계약을 발효하는 것은 차단한다. 기존 계약의 지원되는 적법 종료 뒤 현재 소유권/전체 연결 위상·4단계 제한을 다시 검토하고 별도 최종 서명을 해야 한다. 소속·외교의 실제 적용도 기존 통합 검토 경로를 따른다.

가상 검토에서는 플레이어의 기존 상위 연결 하나만 제외한 예상 위상을 검사하지만 실제 장부에서 그 연결을 제거하지 않는다. 최종 발효 검사는 이 예외를 사용하지 않는다. 하위 계약 조건/기록은 유지하고 이전 종주의 미납 채무도 새 계약으로 삭제하지 않는다. 일반 Offer/NPC-only API의 기존 제한은 유지한다. 구형 JSON은 새 기본 false 필드를 생략하므로 바꾸지 않으며 새 조건부 제안만 표식을 저장한다. 기존 세력/대표/관계/관련 영지가 유효하지 않으면 후보 검토/응답/발효도 보류한다.

## 포로의 기본 모집 상담 기록·개종 목표 보존 (0.3.19)

새 도시 주민 집행 **profile 6**은 포로의 기본 `ResistanceInteractionData` 직전/최종 상담 기록과 등록된 개종 목표 이념 참조를 기존 실제 관리 세력 이전·중단 복구에 연결한다. 상담한 인물 이름과 저항도 감소량·교섭/기분/관계 계수 다섯 필드를 각각 대조한다. 직전/최종 슬롯 이름은 손님 추적기 증거에 포함돼 기록 위치를 바꾸거나 하나를 삭제해도 다르게 판정한다. 기록 없는 상태와 기본값으로 채운 새 기록을 혼동하지 않는다. 실제 상담 객체를 복제·교체하거나 모집을 진행/완료하지 않는다.

개종 목표는 실제 IdeoManager에 같은 원본 참조가 등록돼 있고 ID가 유일하며 형식·관리자 목록을 확인할 수 있는 경우에만 ID를 대조한다. 타깃으로 개종시키거나 바뀐/누락된 목표를 다시 만들지 않는다. 현재 신앙/확신도/교리/과거 이념과 손님 설정·의료/수술·원 소속/포로 신분의 기존 검사도 유지한다. 네이티브 SetGuestStatus가 초기화하는 저항도/의지의 일회 복원 권한은 이력 수정 권한이 아니며, 상담 기록/개종 목표나 이후 진행이 달라지면 계속 보류한다. 커스텀/손상/비유한 기록·미확인/누락/중복 목표는 도시별 영한 이유로 안내한다.

기존 profile 1~5의 지문과 포로 제외 조건은 유지하며 오래된 진행 기록을 새 프로필로 올리지 않는다. 새 기본 프로필만 위 상태를 허용하고, 복구/취소/확정은 저장된 프로필을 사용한다. 기본 형식의 기록·참조는 원래 Pawn_GuestTracker가 계속 저장하며 별도 원본 Deep 사본이나 기록 수리 코드를 만들지 않는다. 지도자의 소속 유지 전출 관측은 기존 고정 프로필을 유지한다.

실제 관리 세력 변경 코드를 확장했지만 **게임에서 포로/상담 기록·목표 이념·Scribe/GC·도시 이전 보존을 실행한 증거는 없다.** 노예·지도자 개인 합류/승계·특수 주민·로딩 맵·전체 합병·일반 전시 가입·정당한 독립은 남아 있으며 1단계는 미완료다. 아래 옛 버전의 모든 모집 상담 기록/개종 목표 차단 설명은 위 제한된 경로에서만 대체한다.


## 지도자의 원 소속·직위 유지 전출 협의 (0.3.18)

개별 도시 이전 화면에 별도 전출 검토를 추가했다. 활성 플레이어 관리 NPC 도시 계약, 출발지에만 저장된 적격 일반 세력 지도자와 같은 세력의 다른 미로딩 도시가 필요하다. 목적지는 활성 도시 계약/미확정 제안에 걸리지 않아야 한다. 제한된 NPC 정책은 소속·직위를 유지하고 검증된 원 세력 도시로 옮기는 제안에만 수락한다. 사용자가 목적지 검토 후 별도의 요청/확인을 해야 기록하며, 도시 계약 서명에서 지도자의 개인 합류 동의를 추론하지 않는다. 개인 합류 거부가 있었다고 만들어 기록하지도 않는다.

집행은 **동일 지도자의 네이티브 previouslyGeneratedInhabitants 참조 배정**을 바꾼다. 별도 준비 기록과 Pawn/도시/세력 원본 참조를 먼저 두고 GC 진행을 취소한 뒤 목적지에 추가하고 출발지에서 제거한다. 소속·지도자 포인터·건강/장비/관계/욕구·의료 설정·수술 지시는 쓰지 않는다. 기존 제한된 주민 보존 관측과 양 도시의 재고/다른 주민 ID 집합·동일 계약 장부를 전후 대조한다. 순수 진단 기록이 아니라 저장되는 실제 도시 참조 변경이지만, 이 네이티브 목록은 향후 Pawn 생성 때 재사용 후보를 우선하는 목록이다. **상단 이동·여행 시간·안전 도착·향후 맵 출현을 구현하거나 보장한 것이 아니다.**

진행 중 정치/계약/초기 구성·새 납부를 막으며, 동일 참조가 목적지에 추가됐지만 출발지에 남은 경우 명시적 재검토로 출발지 제거를 재개한다. 양쪽에서 사라진 주민을 재생성/재삽입하지 않는다. 배정·보존·재고·장부가 모두 원래 상태인 준비만 취소할 수 있다. 자연적인 변화나 소속/직위 변경·도시 상실도 복구를 보류할 수 있다. 불러오기 후 자동 재개하지 않으며 진행 중 지도자 참조만 GC에서 임시 보호하고 해결 후 해제한다. 완료/취소된 협의 증거와 지명/이름은 보존하지만 이후 이전/개인 합류/합병 권한이 되지 않는다.

원래 소속·직위를 유지하므로 후임 선정은 호출하지 않는다. `Faction.TryGenerateNewLeader`는 기존 leader를 먼저 비우고 맵 주민 중 선정하거나 새 Pawn을 생성하며 실패 가능성이 있어, 개인 합류와 안전한 승계/회복은 아직 차단한다. 지도자 역할/작위·유전자/특수 상태·진행 작업/정신 이상·보유/로딩 맵 등 미지원 상태도 계속 차단한다. **1단계는 미완료이며 실제 게임의 이동·보존·Scribe/GC·도시 편입 연결은 미검증이다.**


도시 이전/하위 전체 합의 해약 검토는 노예 보존 미지원, 개종 목표, 미초기화 작업 설정, 할당 재산, 미확인/패치 이념 알림, 이념 역할 등 첫 확인된 보류 사유를 도시 이름과 함께 영한으로 안내한다. 이 설명은 이전 승인·진단 기준 기록·진행 저널을 만들거나 변경하지 않는다. 나머지 미지원 상태는 일반 보류 안내를 유지한다.

노예 이전은 **계속 보류**한다. 설치 DLL에서 `SetGuestStatus(target, Slave)`가 내부 `SetFaction`을 거치며 원래 slave-faction 기록을 지우고 현재 이전 소유 세력으로 다시 기록할 수 있음을 확인했다. 해당 private 기록의 원시 쓰기나 네이티브 손님 처리 우회, 해방/신분 전환으로 대체하지 않는다. 개종 목표/복잡 모집 기록·노예·지도자·특수 주민·로딩된 맵·전체 합병/일반 전시 가입·정당한 독립은 남아 있다. **게임 실행·Scribe·이념/포로 보존은 미검증이며 1단계는 미완료다.** 아래 옛 버전의 전면적인 이념 포로 차단 설명은 위 제한 경로에 한해서만 대체한다.

## 제한된 포로의 관리 주체 이전 (0.3.16)

새 주민 집행은 **profile 4**를 사용한다. 미로딩 도시의 저장 주민에 포함된 적격 일반 포로는 `Pawn.SetFaction` 대신 네이티브 `Pawn_GuestTracker.SetGuestStatus(target, Prisoner)`로 관리 세력만 바꾸며 원래 세력과 포로 신분을 유지한다. 일반 주민과 포로가 섞인 도시도 같은 준비/부분 집행/목적지 대조·확정 흐름을 사용한다. 포로를 해방·노예화하거나 다른 Pawn으로 재생성하지 않는다. 기존 프로필 1/2/3의 조건·지문과 저장된 복구 프로필은 유지한다.

이 네이티브 함수는 저항도·의지·의료 등급과 수술 목록을 초기화한다. 원래 포로 ID/세력, 손님 추적기 설정과 실제 작업 우선순위, 원래 저항도/의지를 별도 증거로 묶는다. 기존 임상/장비/관계/욕구 대조, 의료 등급 복원과 미시작 표준 수술 원본 보관/복원을 함께 적용한다. 저항도/의지는 실제 네이티브 반환 직후 관찰한 값 쌍이 그대로 남아 있을 때만 기록한 원래 값으로 복원한다. 복원 후 해당 권한을 즉시 소진하므로 이후 자연 진행을 옛 초기화 값으로 간주하지 않는다. 네이티브 호출이 관측 전에 중단되거나 다른 설정/진행 값이 바뀌면 추측으로 복원하지 않고 도시와 원래 기록을 보류한다. 자동 재개하지 않는다.

지원 포로는 정확한 기본 Pawn/GuestTracker 타입, 비플레이어 원 소속·관리 세력, 초기화된 작업 설정과 비어 있지 않은 정상 상호작용 모드를 가져야 한다. 원 소속과 목적지가 같은 경우, 손님 처리 함수의 Harmony 패치, 이념/개종·복잡 모집 기록·노예 소속·할당 침대/옥좌/죽음안식 시설·상인 상태·장비 파괴 설정은 차단한다. 정신 이상/쓰러짐/퀘스트/추가 소속/유전자/지도자/작업·영역 제한 등 기존 안전 조건도 유지한다. 로딩된 맵, 노예 및 일반 손님은 아직 지원하지 않는다. 별도 stock에 든 인간은 포로 주민으로 간주하지 않는다.

**코드와 두 참조 빌드/규칙 검증 경로이며 실제 포로·장비·건강·Scribe·알림/GC 보존을 게임에서 입증한 것은 아니다. 1단계는 계속 미완료다.** 아래 옛 버전의 전면적인 포로 차단 설명은 이 제한된 profile-4 경로에 한해서만 대체한다.

## 용도와 상태

사용자가 선택한 전체 흐름 우선 개발의 첫 연결 버전이다. `PoliticalWorld`는 실제 Faction과 별개의 정치 주체 ID를 사용한다. `Honor.Contracts.Preview`는 **별도 선택형 개발 모드**이며 공개 Core/Society/Nobility/Diplomacy/Oaths에 자동으로 포함되지 않는다. 실제 플레이 증명 없이 완성 모드로 Workshop에 게시하지 않는다.

## 이번에 연결한 범위

### 일반 이념 신도의 신앙 유지 이전 (0.3.15)

새 주민 기록의 **profile 3**은 적격 일반 이념 신도도 기존 일반 주민·표준 미시작 수술 지시 이전 경로로 처리한다. 원래 이념 ID, 저장된 확신도, 현재 교리의 ID/Def/타입과 과거 이념 이력을 별도로 요약해 임상·수술 지시 증거와 결합한다. 개종·역할 부여·확신도 쓰기를 하지 않으며 새 목적 세력의 주 이념으로 강제 변경하지 않는다. 소속 변경 뒤나 중단 복구에서 달라진 이념·확신도·교리/이력은 임의 복원하지 않고 보류한다.

이념 역할을 맡은 주민, 노화역행 의무가 있는 이념, 커스텀 교리 타입, 확인하지 않은 소속 변경 콜백이나 해당 콜백에 Harmony 패치가 있는 이념은 보류한다. 설치 DLL에서 확인한 기본 Precept의 빈 알림과 Precept_RoleSingle의 NPC 간 알림만 허용하며, 주민에게 역할이 배정되지 않았음을 별도 확인한다. 저장 확신도는 검증된 private float 필드를 읽는다. public Certainty getter가 아기의 값을 바꿀 수 있으므로 관측에서 호출하지 않는다. 확신도 필드를 확인할 수 없으면 지원을 가정하지 않는다.

기존 profile 1/2의 이념 차단 조건·지문은 유지하고, 옛 미완료 기록의 복구/취소도 저장 profile로 처리한다. profile 3의 새 지문을 옛 기록에 덮어쓰지 않는다. 다른 포로/노예·지도자·유전자/특수 상태·로딩 맵 제한과 엄격한 복구의 자연 변화 보류도 유지한다. **실제 이념/확신도 보존·NPC 알림·UI·Harmony/GC·Scribe 저장 복구는 미검증이며 1단계는 아직 미완료다.** 아래 옛 버전의 모든 이념 주민 차단 설명은 위 경로에 한해 대체한다.

### 시작하지 않은 표준 수술 지시 보존 (0.3.14)

일반 주민의 새 이전 기록은 **주민 보존 profile 2**를 사용한다. 시작하지 않은 기본 `Bill_Medical` 지시를 주민당 최대 15개까지 지원한다. 의식불명/진행 작업, 포로·노예·지도자·이념/유전자/특수 상태 등 기존 주민 제한은 유지한다. 완료/약품 소비 흔적이 있는 수술, 특정 실제 재료나 의사에 결박된 지시, precept/xenogerm·커스텀 Worker 지시는 계속 보류한다. 약품·재료를 소비하거나 진행도를 초기화하지 않는다.

각 지시의 원래 ID·우선순서·레시피·body/부위 인덱스/Def·의료 필터/설정을 기록하고 주민의 기존 건강/장비/관계/욕구 관측과 묶는다. 네이티브 SetFaction의 수술 목록 초기화 전에 **원본 Bill 객체**를 집행 보관 목록으로 옮긴다. 그동안 Pawn 수술 목록은 비어 있고, 원본만 별도 Deep 저장한다. 소속 적용 후 같은 원본을 같은 순서로 되돌리고 집행 보관 목록을 비운다. 지시 재생성·Clone·재발급·ID 재할당은 하지 않는다.

중단 지점이 원본 분리 전/후, 소속 적용 전/후, 원본 복원 후인지 구분한다. 이미 목적 소속인 주민은 다시 SetFaction하지 않고 보관 원본만 복원하며, 복원된 지시를 중복 추가하지 않는다. 일부만 분리되거나 두 보관자에 중복되거나 지시가 없어졌거나 바뀌면 자동 병합/수리하지 않고 원본·기록을 보존한다. 모든 지시가 Pawn 목록으로 돌아오기 전에는 도시 완료나 실행 참조 해제를 허용하지 않는다.

저장 후 로딩에서 unsaved billStack 연결을 동일 주민의 수술 목록에 바인딩한다. 원래 부위 참조가 저장 당시 존재했는데 네이티브 디코딩에서만 누락된 경우에는 원래 ID·레시피·기타 설정과 현재 해부 구조까지 모두 대조한 뒤 기록된 참조를 채운다. 저장 전부터 지워진 부위나 다른 비-null 부위를 덮어쓰지 않는다. 이 과정은 보관 데이터 재연결이며 계약/소속 이전을 자동 재개하지 않는다. 손상된 자료는 실패 상태와 원본을 남긴다.

0.3.13의 profile 1 미완료 기록은 원래 지문·빈 수술 목록 조건을 유지한다. 복구/취소 관측도 저장된 profile을 사용하여 새 profile의 지문으로 덮어쓰지 않는다. **1단계는 여전히 미완료다.** 실제 게임의 수술 목록/원본 객체 보존·Scribe 디코딩·Harmony/GC·예외 복구는 실행 검증하지 않았다. 아래 옛 버전의 모든 수술 지시 차단 설명은 위 좁은 경로에 한해 대체한다.

### 실제 파괴된 말단 영지의 계약 종료 (0.3.14)

새로 발생한 네이티브 WorldObject.Destroy의 정상 종료를 관찰한다. 파괴 전 실제 등록된 기본 NPC Settlement와 계약 바인딩·기존 소유권 이력이 일치하고, 파괴 후 Destroyed 플래그와 세계 목록 제거를 확인하며 계약 장부가 중간에 바뀌지 않았을 때만 적격 말단 영지의 활성 상위 계약을 `TerritoryLost`로 종료한다. 원래 조건·양측 서명·일부 해약 동의·다른 계약과 집행 이력은 유지한다. 플레이어 그룹이나 개인 서약을 끝내거나 주민·물품·채무를 지우지 않고, 공격자나 불명예를 추정하지 않는다.

활성 하위 봉신이나 관련 미확정 제안, 진행 중 이전/정치/공납, 검증할 수 없는 실제 소유권이 있으면 자동 종료하지 않는다. 점령에 의한 소속 변경·상위 영지 승계·옛 저장의 사라진 참조·중단된 파괴 호출을 이 경로로 처리하지 않는다. 재건/새 영지는 새 계약이 필요하며 종료된 지시를 자동 부활시키지 않는다. 말단 파괴 처리만 추가한 것이므로 전체 영지 소실/승계는 여전히 미완료다. 실제 게임에서 파괴 이벤트·저장·UI를 실행 검증하지 않았다.

### 제한된 일반 주민의 실제 이전·의료 복원 (0.3.13)

개별 도시 이전, 전체 봉신 정렬/소속 전환과 하위 전체 합의 해약 이주에서 **지원되는 일반 저장 주민 1~128명**을 네이티브 Pawn.SetFaction으로 목적 NPC 세력에 편입한다. 주민 원본 참조를 유지하며 새 Pawn을 생성하거나 faction 필드를 직접 쓰지 않는다. 새 주민 정책 전체의 완성이 아니라 제한된 첫 실행 경로다.

도시는 미로딩이고 모든 저장 주민이 생존한 기본 인간형 월드 Pawn이어야 한다. 수술 지시가 있는 주민, 포로/노예/손님, 지도자/작위, 이념/유전자/변이·특수 상태, 퀘스트/추가 소속, 진행 작업/정신 이상/쓰러짐, 다른 보관자/Lord, 영역/주인 제한이나 미지원 컴포넌트가 있으면 도시 전체의 새 물리 이전을 보류한다. 수술 지시를 삭제하는 대신 **비어 있는 수술 목록만** 지원한다. 포로·노예의 신분 유지와 지도자의 별도 동의/후임 선정은 확정 명세지만 아직 실행하지 않는다. 이미 목적 세력에 있는 도시에는 새 주민 소속 변경을 실행하지 않는다.

준비 전에 주민별 ID·기존 소속·관측 건강/장비·직접 관계/기억·욕구·일부 의료 외 설정과 원래 의료 등급을 수집한다. 정렬한 주민 집합의 별도 ResidentProof를 도시 집행 이력에 저장하고 실제 Pawn 참조와 함께 복구 자료로 보관한다. 네이티브 소속 변경 후 기록한 의료 등급만 복원하고 관측 보존 항목과 최종 소속을 대조한다. 모든 주민 확인 후에 도시 소속을 바꾸고 재고/주민 증거를 대조해야 완료한다. 기존 진단 기준 기록은 이 권한이나 증거로 쓰지 않는다.

변경 전에 진행 중임을 기록하며 예외 시 일시정지·미완료 기록 보존을 수행한다. 중단된 도시의 **복구**는 현재 대표 계약/목적 권위·외교·원래 주민 참조/상태·기존 재고를 다시 검사한다. 이미 목적 소속인 주민에게 SetFaction을 반복하지 않고, 허용된 원 소속 주민만 앞으로 이전한다. 원래 의료 등급만 복원하며 제삼자 소속·건강/장비/관계/욕구 차이·누락 참조는 강제로 수리하지 않는다. 아직 시작하지 않은 건은 실제로 모두 미변경일 때만 기존 취소 경로를 사용한다. 다른 정치 변경·초기 구성·새 공납 전달은 준비 도시가 있는 동안 차단한다. 불러오기에서 자동 재개하지 않는다.

진행 중 집행 참조만 WorldPawnGC의 기존 중요 사유가 없을 때 임시 보호한다. 원래 ForcefullyKeptPawns 집합을 바꾸지 않고, 완료/취소 후 실행 참조를 해제한다. 완료 이력은 실제 주민이 나중에 이동/사망/변경되더라도 현재 주민 집합과 계속 같을 것을 요구하지 않는다. 해당 GC 패치가 없으면 새 주민 이전은 보류한다.

복구는 엄격한 대조 방식이다. 시간 경과로 생긴 나이/욕구/건강/기억 변화도 보류 사유가 될 수 있으며 이를 자동 손실·위반·불명예로 판정하지 않는다. 전체 Pawn/모드 상태를 직렬화해 복원하는 기능은 아니고 제한된 관측 요약의 일치도 완전 보존 증거가 아니다. **게임 실행·UI·Harmony/GC 적용·Scribe 복구·실제 주민/물품 보존은 여전히 미검증**이다. 아래 옛 버전의 모든 주민 차단 설명은 위 제한된 경로에 한해 대체한다. 1단계는 계속 미완료다.

### 하위 영지 전체의 합의 해약·연합 이전 (0.3.12)

실제 계약 장부에서 **NPC 하위 영지 전체를 합의 해약 후 연합으로 이전**을 연다. 현재 플레이어 공동 소속에 실제 정렬된 NPC 종주 도시를 선택하면 그 도시와 모든 간접 후손, 현재 대표 동의·우호도·외교·미완료 장부·원 세력 누적 잔여 도시 수·물품 보존을 검토한다. 기존 자유도시연합과 유효한 대표가 필요하다. 현재 대표 동의는 우호도 50 이상인 기존 대표 판단 경로이며 귀족 투표/연합 평의회 시스템을 구현한 것은 아니다.

확정 시 최상단의 상위 계약만 양측 합의 해약하고 **내부 봉신 계약·공납 조건·옛 기록·기존 채무는 그대로** 둔다. 미리 검증한 장부를 한 번에 교체한 뒤 각 도시를 실제 연합 세력으로 이전한다. 플레이어 소속이나 native 플레이어 Pawn/정착지 소유권은 바꾸지 않는다. 전체 도시의 실제 목적 소유권과 개별 집행 이력 확인 전에는 완료하지 않는다. 계약 해약/의도/도시별 적용을 분리해 저장하며 다른 정치 변경·새 공납 전달·세계 재편과의 경합을 차단한다.

중단하면 같은 화면에서 남은 도시를 검토·재개한다. 준비 중인 도시가 있으면 먼저 개별 복구를 실행한다. 적용되지 않은 준비는 장부와 도시 집행 장부가 모두 그대로인 경우에만 취소할 수 있고, 이미 합의 해약한 계약은 취소 버튼으로 되돌리지 않는다. 불러오기에서 자동 재개하지 않는다. 완료한 이탈의 근거도 보관하여 후속 장부 변경이 과거 도시 이전 증거를 지우지 않는다. 과거 도시 집행 JSON에는 null 필드를 쓰지 않아 구형 취소 요약을 유지한다.

실제로 이동할 도시의 주민·로딩 맵·미지원 재고는 여전히 차단한다. 원 세력 마지막 도시에는 전체 합병 동의·보존·복구 구현이 먼저 필요하며 기존 가드를 유지한다. 검증된 연합 전쟁 부담 수락이 없는 새 전시 가입도 차단한다. 해당 도시에 이름과 보류 사유를 영한으로 안내한다. 이미 연합 소속인 도시는 새 물리 이전 없이 소유권을 확인한다. **1단계 미완료이며 게임 실행/저장 재개/자원 보존의 런타임 증거는 없다.** 아래 이전 버전의 미지원 목록 중 하위 전체 합의 해약 이주는 이 제한된 경로로 대체한다.

### 1단계 진행: NPC 초기 계층·하위 봉신과 거래 동물 (0.3.11)

실제 정착지 계약 장부의 **초기 NPC 봉신 관계 구성**에서 미등록·비적대 일반 NPC 세력의 기존 도시 일부를 초기 내부 봉신으로 배치한다. 세력의 살아 있는 대표가 자체 영지를 배치하는 초기 세계 설정이며 플레이어와 협상한 독립이 아니다. 비율과 최대 30개 도시를 검토한 뒤 확정하면 같은 실제 장부에 활성 NPC 계약을 생성한다. 기존 세력→도시→도시→도시로 최대 4단계 분기를 만들며 원래 소속·맵·주민·재고를 바꾸지 않는다. 왕실/연합/플레이어 관리청·기존 등록 세력·적대/임시/숨김/멸망/영구 적대 세력은 제외한다. 서명·참조·일회 설정 기록을 저장하고 복원 검사한다. NPC 공납 재고나 군사 사건을 생성하지 않는다.

**NPC 봉신 계층 관리**에서는 현재 플레이어 공동 세력에 실제 편입된 봉신의 직속 종주를 다른 봉신으로 바꾸거나 플레이어 직속으로 복귀시킨다. 현재 NPC 세력 대표·플레이어 우호도 50 이상·실제 소속·연결 영지의 가용성·미완료 장부와 전체 후손의 4단계 한도를 검토한다. 원래 고정 공납 조건을 유지해 옛 계약의 합의 해약과 새 계약 양측 서명을 복사본에서 전부 검사한 뒤 장부를 한 번에 교체한다. 옛 기록과 후손의 정확한 계약을 유지하며 새 NPC 자원을 만들어 납부하지 않는다. 초기 NPC 세계의 플레이어 관할 밖 영지에는 이 재배치 권한을 주지 않는다.

NPC 계약은 별도 두 NPC 대표 정보와 서명 경로를 사용한다. 기존 JSON 서명 필드 이름은 호환성을 위해 남기지만 NPC 모드에서는 첫 슬롯이 종주, 둘째가 봉신이며 플레이어 서명으로 표시하거나 대신 서명하지 않는다. 기존 플레이어/NPC 기록에 새 필드를 쓰지 않아 옛 장부 JSON과 취소 해시를 유지한다. NPC 대표가 바뀌어도 옛 서명 기록을 지우지 않으며 새 재배치에는 현재 대표를 확인한다. NPC 사이 개인 봉신 서약을 구현한 것은 아니다.

플레이어의 소속 통합 전환과 별도 일괄 정렬은 이제 직속뿐 아니라 **모든 간접 NPC 후손**을 검토·이전한다. 도시별 실제 목적 소유권 확인과 원 세력 누적 기지 수 보호, 부분 완료/중단 복구를 유지한다. 반면 단일 NPC 종주 도시의 해약으로 후손을 남겨 두는 것은 차단하며 자식의 재배치를 먼저 요구한다. 하위 전체의 합의 해약 후 연합 이주, 외부 세력 사이 NPC 재협상·전시 이전은 아직 남아 있다.

적대 전환 중 **이전 플레이어 종주가 실제 양측 해약을 승인한 경우**에는 그 정확한 출발 세력의 활성 플레이어 봉신 도시만 허용한다. 새 목적지 수락·퀘스트/우호도 제한·본래 소유권·4단계/잔여 기지·재고/주민 검사를 모두 유지한다. 준비/중단 전환에서는 저장한 이전 명령과 동일한 대상 소속을 재검증하며 완료 뒤 예외를 남기지 않는다. 무관한 적대 원 세력·일방 이탈에는 적용하지 않고 외교 관계를 중립으로 덮어쓰거나 허위 위반·선전포고를 생성하지 않는다. 정상 계약 관측은 그대로 유지하고 제한된 이전 관측만 해당 출발 세력과 활성 후손에 한정한다.

실제 소속 이전의 재고 검사에는 제한된 거래 동물을 추가했다. 살아 있고 쓰러짐/정신 이상/진행 작업/손님 상태가 없으며 월드 주민으로 등록된 기본 Pawn 타입 동물, 동일 거래 보관자에 있고 장비·의복·소지품·운반 물품이 없는 경우만 허용한다. 사람·시체·중첩/축소 물품과 미지원 동물은 계속 제외한다. 동물 ID·종류·기존 소속·관측 건강/장비/상태를 물품과 함께 요약하고 집행/복구 시 형식까지 대조한다. 동물의 SetFaction은 호출하지 않고 원래 객체와 소속을 유지하며 재생성/압수/복제를 하지 않는다. 모든 훈련·욕구·컴포넌트 상태의 전수 보존 증거를 주장하지 않는다. 보통 재고의 기존 요약과 과거 준비 건은 형식을 바꾸지 않는다.

**1단계 전체 완료는 아니다.** 주민의 주요 상태/의료 설정/수술 지시 보존과 현재 작업/예약 종료 허용, 포로/노예 신분 유지, 지도자의 별도 동의 후 합류/원 세력 후임 선정 정책을 확정했다. 이는 구현 완료가 아니며 네이티브 Pawn.SetFaction의 초기화에 대한 보존/복구 구현이 필요하다. 로딩된 맵의 물리 이전·인간/복잡 재고·전시 이적·검증된 중대 위반에 의한 일방 독립·영지 소실 정리와 하위 전체 해약 이주도 남아 있다. 진단 값이나 개발 버튼으로 허위 위반 증거를 만들지 않는다. 게임/Mono 실행·UI·Scribe·Harmony·물품·주민 보존은 계속 실행 검증하지 않았다.

### 1단계: 주민 기준 기록 저장과 비교 (0.3.9)

도시 점검 화면에 `주민 기준 기록 저장`·`기준 기록과 비교`·`기준 기록만 삭제`를 추가했다. 미로딩 NPC 도시의 저장 주민 목록을 읽고, 하나의 기준 기록을 별도 GameComponent에 보관한다. 저장 시 다른 도시의 기록도 교체하므로 화면에서 현재 기록의 도시 일치 여부와 시각을 표시한다. 비교는 같은 도시·기준 이후 시각에만 허용하며, 현재 목록 전체를 새로 읽는다. 자동 기준 저장·비교·재집행은 하지 않는다. 기준 기록이 손상되면 원본 JSON을 유지하고 이 점검 기능만 보류한다. 명시적 삭제는 기준 기록만 지우며 계약/영지 집행 장부에는 영향을 주지 않는다.

고정 주민 ID와 소속, 건강 상태의 ID/Def/부위 Def/Severity, 직접 장비·의복·소지품의 ID/Def/재료/수량/내구도/품질, 일부 생존·위치·포로/노예·지도자·정신 상태/현재 Job Def를 요약한다. 주민 순서 변경은 무시하며 추가/누락과 소속·건강·장비·상태 변경을 각각 집계한다. 같은 주민에 여러 변경이 겹칠 수 있다. 원본 기준 기록은 비교로 덮어쓰지 않는다. 이름 대신 ID와 요약을 저장하고 주민을 별도 보존 참조로 붙잡거나 새로 생성하지 않는다.

최대 1,000개 주민 참조를 허용하며 누락/중복 주민, 알 수 없는 Pawn 하위 클래스, 중첩 보관함/미지원 장비 및 잘못된 입력은 저장을 거절한다. 저장용 JSON은 버전·크기·ID·요약 형식·시각을 검사한다. JSON 규칙 왕복은 실제 Scribe 저장/로드 증거가 아니다. 정상 시간 경과로 부상·내구도·작업 등이 바뀔 수 있으며 참조 누락은 사망/손실 증거가 아니다. 모든 의료 설정·예약·욕구·생각·이념·모드 상태를 추적하지 않으므로 **동일 요약은 완전 보존이나 이전 권한을 증명하지 않는다.** 주민 소속 집행/복구는 계속 미지원이며 실제 플레이 검증과 Workshop 게시도 보류한다.

### 1단계: 도시별 주민·재고 읽기 전용 점검 (0.3.8)

**플레이어 정치 소속** 또는 **봉신 일괄 소속 정렬**에서 `점검할 봉신 도시 선택`, 개별 영지 소속 창에서 `이 도시의 주민·재고 점검`을 연다. 활성 직속 봉신 도시를 골라 현재 세력·로딩 맵 여부·원 세력 정착지 수·기존 거래 재고와 저장 주민 참조를 관측한다. 진행 중 정치 전환에서도 점검은 허용하되 집행·완료·취소 권한을 부여하지 않는다. 주민/물품/장부를 바꾸거나 재고를 생성하지 않고, 상태 변화 후에는 명시적 새로고침을 사용한다.

저장 주민의 누락·중복·사망/파괴·맵/다른 보관자·월드 주민 부재·플레이어/다른 세력·지도자·포로/노예 참조를 표시한다. 같은 참조에 여러 주의 항목이 겹칠 수 있다. 전체 참조를 집계하고 이름은 처음 20개까지만 표시한다. **주의 항목이 없어도 보존/이전 권한을 증명하지 않는다.** 저장된 주민이 있으면 기존 이전 차단은 유지한다. 재고 항목 수는 스택 안 물품 개수가 아니며 사람·동물·시체·중첩 보관함 등은 실제 이전과 공유하는 분류기를 사용한다. 맵 내부 주민을 전수 조사하거나 퀘스트/문화/장비 보존을 검증한 보고서는 아니다.

설치 DLL의 Pawn.SetFaction은 guest status, surgery bills, medical care, mind/job 상태와 관계·이념 알림까지 처리한다. 따라서 소속 필드 변경만으로 주민 이전을 완료했다고 가정하지 않는다. 실제 주민 집행·보존할 상태의 명세·개별 주민별 저장/복구는 후속 구현이며 이번 점검은 읽기 전용 준비 기능이다. 코드/컴파일/언어 검사만 수행하고 실제 UI·도시/주민·엔진 저장은 실행하지 않는다.

### 1단계: 방문 도시의 일반 거래 물품 보존 (0.3.7)

기존 계약의 개별 소속 집행과 통합 봉신 이전에서 **이미 거래한 NPC 도시도 맵이 미로딩이고 저장된 주민이 없으면** 일반 물품을 보존한 채 이전하도록 작성했다. 초기 세계 재편/연합 배치는 계속 미방문 도시만 사용한다. 사람·동물·시체·축소 건물·직접/컴포넌트 보관함 재고, 알 수 없는 정착지/상단 하위 클래스는 제외한다. 플레이어 기지와 Pawn 소속은 바꾸지 않는다.

검토 시 `GetDirectlyHeldThings()`로 현재 재고만 읽으며 `Goods`/`StockListForReading`으로 재생성하지 않는다. 물품 ID·Def·재료·수량·내구도·품질, 방문 여부·보관자 존재·재입고 시각을 SHA256으로 요약한다. 검토 후 재고가 바뀌면 다시 검토해야 한다. 준비 장부에 같은 근거를 저장하고 실제 목적 소속과 동일 재고를 확인해야 완료한다. 중단 복구 때 출발 소속 그대로여도 재고가 다르면 취소하지 않고 보류한다. 이 요약은 열거한 상태의 변경 감지이며 모든 물품 컴포넌트 상태/모드 호환성이나 저장 파일 보안 인증을 보장하지 않는다.

기존 재고를 버리거나 복제하지 않으며 이미 만료된 재고가 없는 도시도 새 물품 없이 검사한다. 목적 세력의 거래 종류는 native getter를 따르고 향후 재입고·주민 생성은 목적 세력 기준이다. 도시 표시 material 캐시만 비우며 풀의 material을 파괴하지 않는다. 옛 v1 실행 기록의 새 필드는 null이면 쓰지 않아 미변경 장부 JSON과 진행 중 정치 전환의 취소 해시를 유지한다. 이전 개발판의 미방문 전용 준비 건을 새 방문 증거로 승격하지 않는다.

실제 맵/주민·특수 재고 이관, 문화 보존, 전시 점령·NPC 다단계 계층은 남아 있다. 새 코드와 규칙 검사·설치 DLL 빌드만 검증하며 실제 자원 보존·캐시 갱신·엔진 저장/복구·다른 모드 패치는 게임 실행으로 검증하지 않았다. 1단계 완료나 Workshop 공개판을 뜻하지 않는다.

### 1단계: 소속·봉신 이동 통합 전환 (0.3.6)

**플레이어 정치 소속**에서 연합 가입, 합의 해약 후 연합 복귀, 서명된 새 종주 계약을 검토할 때 대외 관계와 모든 활성 직속 NPC 봉신 도시 목록을 함께 표시한다. 기존처럼 플레이어 이적 후 별도 일괄 버튼을 반드시 눌러야 하는 흐름을 바꿨다. 한 번 확정하면 플레이어 소속 명령→공유 외교→도시별 실제 이전→전체 목적지 확인을 이어서 수행한다. 기존 저장의 수동 정렬 화면도 유지한다. NPC끼리의 다단계 생성/후손 전체 집행을 구현한 것은 아니다.

이전 봉신 계약의 실제 양측 해약·기록된 종주 일치, 새 계약의 활성 상태/실제 권위자, 연합 통보기간과 미완료 물품 이전, 살아 있는 목적 세력 대표·퀘스트/우호도 상한, 봉신 전체의 누적 이전 가능성을 먼저 검사한다. 연합 복귀에는 이미 존재하는 유효한 연합이 필요하다. 새 외교에서 봉신 원 세력과 적대하게 되면 이 평화 이전 어댑터로 이동하지 않고 시작 전에 보류한다. 당시에는 방문/로딩된 도시의 새 소속 이전을 보류했으며, 0.3.7에서 아래 제한에 따라 일반 물품 방문 도시에 한해 확장했다. 이미 목적 세력에 도착한 방문 도시는 다시 옮기지 않는다.

`AllegianceTransitionLedger`/`PoliticalTransitionLedger`는 하나의 준비/소속 적용/완료/취소 의도를 버전 1 JSON으로 저장한다. 이전·예상 소속 명령 이력과 대상 계약 집합, 이전 영지 장부의 SHA256 및 확인 시각을 보관한다. 해시는 취소 시 장부 일치 확인용이며 저장 파일의 보안 인증이 아니다. 소속 기록만으로 도시 이전 완료를 주장하지 않는다. 과거 전환 이력은 PlayerAllegiance 명령과 도시별 장부에 남고 조정 장부에는 현재 또는 마지막 의도만 둔다.

중단된 경우 이 창에서 미확정 도시를 확인하고 **현재 목적지와 남은 도시 재검토** 후 재개한다. 원래 명령 이력의 동일한 앞부분과 현재 소속·계약, 실제 해약/활성 계약 및 정확한 봉신 집합을 다시 확인한다. 같은 권위자의 중단/재확인 명령은 허용하지만 다른 정치 소속으로 바뀐 이력으로 완료 처리하지 않는다. 소속 적용 전이고 플레이어 명령 이력과 영지 장부가 그대로인 준비 건만 취소할 수 있다. 부분 적용된 소속·도시는 자동 롤백하지 않는다. 로드 후 자동 재실행도 하지 않는다.

진행 중에는 다른 계약/소속 변경·초기 세계 재편·관리청 설립/재개·새 실물 납부를 보류한다. 실제 소유권 확인/미이동 취소는 허용한다. 기존 미납·영수증·해약 기록은 보존하며 복귀나 이적이 채무를 면제하지 않는다. 연합 회비·정당한 일방 독립·사라진 권위자에 대한 비상 전환은 미구현이다. 외부 모드가 대상 계약/세력을 변경해 검증할 수 없으면 보류 상태를 유지한다.

추가 54개 순수 검사, 설치 DLL 빌드와 영한 키를 검증했다. 실제 전환 창·외교 알림/재진입·세력/도시 변경·엔진 Scribe 왕복·중단 복구는 실행하지 않았다. 코드 단계 구현을 실제 플레이 성공으로 취급하지 않으며 1단계 완료/Contracts Workshop 게시도 보류한다.

### 1단계: 영지 관리청과 봉신 일괄 소속 정렬 (0.3.5)

플레이어 정착지의 **플레이어 정치 소속** 창에서 미소속 상태에 **NPC 영지 관리청 설립**을 선택한다. 실제 비플레이어 세력을 하나 만들고 플레이어와 +100 내부 동맹으로 시작한다. 숨김 생성 override로 무작위 정착지 생성을 억제한 뒤 공개 세력으로 등록한다. 관리청은 플레이어의 종주가 아니며, 독립 플레이어의 봉신 도시를 플레이어 기지로 바꾸지 않고 수용하는 NPC 소속 표현이다. 생성/저장 ID·플레이어 ID를 검증하며 중복/멸망 관리청을 임의로 교체하거나 부활시키지 않는다.

`RealmAdministrationLedger`는 플레이어의 대외 우호도/관계 종류를 관리청에 복사하고 관리 도시의 대외 우호도 사건을 플레이어 쌍으로 전달한다. 외국 종주 외교 공유는 관리청을 별도 대상으로 덮어쓰지 않으며 플레이어와 자기 관리청의 내부 사건도 외국 종주로 우회하지 않는다. 퀘스트/영구 관계 제한·플레이어 상한·소속 중단·내부 적대 충돌 시 관리청 공유를 멈추고 재검사를 요구한다. 무작위 습격·군사 원조·퀘스트 장소 생성은 비활성화했지만 일반 NPC 세력 조회에서 보이므로 모든 퀘스트/모드 호환성을 보장하지 않는다. 바닐라의 내부 우호도 변화도 남아 있다.

관리청의 초기 병종/기술/거래/이념은 OutlanderFactionBase의 산업 외지인 기준이다. 플레이어 기술이나 주민 문화를 복제한 것이 아니다. 현재 언어에 맞는 세력명과 6개 DefInjected 필드를 제공한다. 플레이어 도시·Pawn의 faction은 변경하지 않는다. 관리청 설립 후 실제 계약 장부의 NPC 영지 소속 집행이나 아래 일괄 화면에서 도시 편입을 따로 확정한다.

같은 정치 소속 창의 **현재 정치 소속으로 봉신 도시 정렬**에서 활성 NPC 도시 봉신 전체를 현재 관리청/연합/종주 세력과 대조한다. 누락/중복 대상을 거절하고 각 도시의 실제 소유권·미방문 조건·미완료 이전과 같은 원 세력의 누적 도시 감소를 장부 복사본으로 먼저 검사한다. 실제 원 세력에는 다른 기지를 남긴다. 검증된 플레이어 전용 관리청만 모든 도시가 빠져나가 빈 상태가 될 수 있다. 이미 목적 소속인 도시는 방문/맵이 있어도 이동할 필요가 없지만, 다른 소속의 방문 도시는 여전히 이동을 막는다.

일괄 확정 후에도 실제 이전은 도시별 준비→SetFaction→소유권 확인으로 순차 처리한다. 중단 시 완료 건은 유지하고 미완료 도시를 복구 버튼으로 확인한 뒤 전체를 다시 검토한다. 일부 완료를 전체 성공으로 기록하지 않으며 집행 중 목적지·활성 대상이 달라졌는지도 끝에 검사한다. 저장 후 새로운 세계 상태에서 목록을 다시 만들며 과거 계획을 자동 재실행하지 않는다. 이 0.3.5 독립 정렬 화면에 더해 위 0.3.6에서 소속과 직속 봉신의 통합 확정을 추가했다. 현재 실제 장부가 지원하는 플레이어 직속 NPC 도시만 취급한다. NPC끼리의 다단계 생성은 남아 있다.

추가 37개 순수 검사, 설치 DLL 빌드와 영한 번역을 검증했다. 실제 관리청 생성·외교 재진입·이름 표시·NPC 도시/주민·세력 멸망 판정·퀘스트·Scribe 저장 재로딩은 실행하지 않았다. Contracts Workshop 게시와 1단계 완료 판정은 보류한다.

### 1단계: NPC 영지 소속 집행 (0.3.4)

실제 계약 장부에서 NPC 도시가 봉신인 활성/합의 해약 계약의 **NPC 영지 소속 집행 / NPC territory membership** 창을 연다. 현재 도시·원 세력·목적 세력을 검토한 뒤 별도 확정한다. 활성 계약은 플레이어가 이미 가입해 공유 외교를 적용 중인 비플레이어 연합/종주 세력을 목적지로 삼는다. 합의 해약 계약은 초기 구성 등으로 이미 존재하는 자유도시연합으로 이동한다. 진행 중 제안이 있으면 먼저 해결해야 하며 새 활성 계약이 있으면 옛 해약 기록으로 이를 우회할 수 없다. 이미 목적 세력 소속이라면 추가 이동을 만들지 않는다.

**확정은 실제 NPC 정착지의 Faction을 바꾸며**, 편입 후 대외 외교·향후 주민 생성·거래·기술/이념은 목적 세력 기준이 된다. 기존의 서명 동의 장부는 보존한다. 지금은 로딩된 맵·방문/재고/주민 생성 이력·적대/숨김/임시/멸망/왕실 작위 세력·미완료 실물 이전을 제외하고 원 세력에 다른 기지가 남아야 한다. 대상·목적지 자격과 실제 소유권을 확정 시 다시 검사한다. 플레이어 기지와 Pawn의 소속은 변경하지 않는다.

`TerritoryTransferLedger`는 준비/적용/취소, 원본 정체성·실제 출발/목적 소속·계약·시각을 별도 버전 1 JSON으로 저장한다. 실제 도시/세력 참조는 Scribe로 저장한다. 준비만으로 완료를 주장하지 않으며 실제 목적 소유권·미방문 상태를 확인해야 적용된다. 중단된 건은 실제 목적 소속이면 확인하고, 출발 소속 그대로임을 확인해야 취소한다. 제삼자의 소유권을 강제로 덮어쓰거나 재이동하지 않는다. 해결 전에는 후속 이동과 해당 도시의 계약 동의를 보류한다.

계약의 최초 native owner는 불변의 기준 ID다. 실제 소속이 실행 장부의 마지막 완료 목적지와 일치할 때만 계약 관측에서 최초 정체성에 대응시킨다. 진행 중 이동·현재 외부 점령·소실은 정상 관측으로 변환하지 않는다. 같은 도시와 후속 계약을 다시 맺을 때도 원본 ID를 새 세력 ID로 덮어쓰지 않는다.

독립 플레이어의 봉신 도시를 native `Faction.OfPlayer`로 편입하면 바닐라 플레이어 기지가 되므로 이번에는 이를 거절한다. 영지 관리청과 이적 후 별도 확인형 일괄 정렬은 위 0.3.5 절에서 추가했다. 직속 봉신의 통합 이적과 플레이어의 합의 해약 후 연합 복귀는 위 0.3.6에서 추가했다. 방문한 도시의 맵/주민/재고 보존, NPC끼리의 계층 생성/다단계 후손 집행, 주군 중대 위반에 따른 일방 독립은 남아 있다. **해약 자체가 자동 이동이나 전쟁/보호 임무 완료를 뜻하지 않는다.** 이 제한 중 일반 거래 물품 보존은 0.3.7에서 확장했으며 로딩된 맵·저장된 주민·사람/동물/보관함 재고 이전은 계속 제외한다.

추가 69개 순수 검사와 기존 전체 빌드가 통과했다. 실제 엔진의 소유권 변경·캐시·세력 멸망 판정·생성 주민·거래·저장 복원은 실행하지 않았다. 1단계는 여전히 진행 중이며 Contracts Workshop 배포는 보류한다.

### 1단계: 플레이어 소속과 공유 외교 (0.3.3)

플레이어 정착지의 **플레이어 정치 소속 / Player political allegiance** 명령을 추가했다. 초기 구성에서 만든 연합 가입 또는 실제 장부에 양측이 서명한 플레이어 봉신 계약의 종주를 검토한다. 후보의 공개 대외 관계를 표시하고 별도 확정해야 적용하며, 검토 이후 원본 관계가 바뀌면 재검토를 요구한다. NPC 동의는 연합의 살아 있는 지도자·비적대 상태 또는 기존 양측 서명 계약을 기준으로 하는 임시 정책이다. 초기 기지 가치 성장 알림과 정치 협상 AI는 아직 연결하지 않았다.

확정 시 **모든 플레이어 정착지의 실제 대외 우호도와 적대/중립/동맹 관계가 종주/연합을 따른다.** 종주/연합과의 내부 관계는 +100 동맹으로 시작한다. 세력의 실제 관계 객체를 별도로 유지하면서 값을 복사하고 바닐라 관계 변경 알림을 호출한다. 플레이어가 관련된 우호도 사건은 원래의 변경 허용 조건과 자연 우호도 보정을 확인한 뒤 대표 세력에 전달한다. 이후 외교 변화도 즉시 또는 250틱 주기로 공유하며 관계 종류 변경은 메시지와 일시정지로 알린다. 평의회 표결/전쟁 승인 기능은 아직 없으므로 현재는 플레이어의 외교 사건이 공유 관계에 직접 영향을 준다.

Pawn·Settlement의 native player faction은 바꾸지 않는다. 소속 때문에 식민지 조작을 NPC에 넘기거나 게임을 종료하는 코드를 추가하지 않았다. 퀘스트 관계 잠금·플레이어 전용 우호도 상한이 원본 관계와 충돌하면 공유를 중단한다. 종주 소실·내부 적대·계약 무효화도 같은 방식이며 마지막 관계/계약 기록은 보존한다. 문제 해결 후 같은 권위자의 유효성·동의를 다시 확인해야 재개한다. 중단 상태는 정상적인 독립 판정이 아니며 모든 관계를 가입 전으로 자동 복구하지 않는다. 다른 모드의 임의 관계 객체 직접 수정과 모든 퀘스트 경로의 호환성을 검증한 것은 아니다.

`PlayerAllegiance`는 고정 native player ID와 전환 명령을 버전 1 JSON으로 저장·재생한다. 기존 봉신 계약이 실제로 해약되기 전 다른 계약이나 연합으로 이중 편입하지 못한다. 연합에서 새 종주로 가려면 3일 전 통보, 서명된 새 계약, 미완료 물품 이전 해소가 필요하다. 통보를 다시 눌러 기간을 줄일 수 없다. 연합 회비는 아직 없으므로 이 확인은 미래의 모든 연합 의무 정산을 구현한 것이 아니다. NPC 영지의 제한된 수동 Faction 이동은 위 0.3.4 절에서 추가했다. 플레이어의 해약 후 자동 연합 가입과 정당한 일방 독립은 후속 작업이다.

추가 72개 순수 검사는 동의·기존 계약 해약·통보기간 경계·중단/재확인·저장 재생·손상 입력과 독립된 관계 스냅샷을 검증한다. 실제 게임의 창·Harmony 패치·외교 사건·일시정지·Scribe 재로딩·플레이어 통제는 실행 검증하지 않았다. **1단계 전체 완료나 Workshop 배포 가능한 검증판을 의미하지 않는다.**

### 1단계: 실제 NPC 자유도시연합 초기 배치 (0.3.2)

모드가 활성화된 세계를 처음 열면 **기존 세계 유지 / 초기 자유도시 구성**을 선택하는 창을 제시하도록 작성했다. 닫으면 선택을 미루고, 확정 전에는 소유권을 바꾸지 않는다. 선택은 저장 게임별로 기록한다. 플레이어 정착지의 **초기 정치 질서 설정** 명령으로 다시 열 수 있다. 새로운 행성 생성기 자체의 설정 화면/봉신 계층 생성기는 아직 아니며 시작/불러오기 이후에 동작하는 초기화 단계다.

기존 유지 선택은 도시 소속을 변경하지 않는다. 구성 선택은 적격 도시의 0~30%(기본 10%), 최대 10개·원 세력당 1개를 미리 표시하고 확정 후 실제 `Settlement.SetFaction`으로 하나의 `HonorContracts_FreeCityUnion` 세력에 편입한다. 같은 native faction에 속하므로 편입 NPC 도시들은 바닐라 대외 관계를 공유한다. 기존 도시의 개별 원 세력 외교 대신 연합 외교·기본 산업 기술 병력/거래·이념이 적용되며 이를 확정 전에 표시한다. 인물/맵별 문화·병종 보존은 후속 작업이다.

플레이어 세력, 로딩된 맵, 방문/재고 생성 또는 주민 생성 이력이 있는 도시, 계약 장부에 등록된 도시, 적대/영구 적대 세력, 숨김/임시/멸망 세력, 비인간형 세력, 왕실 작위 체계를 가진 세력, 원 세력의 마지막 정착지는 제외한다. 확정 직전에 실제 소유자·정착지 수·모든 조건을 재확인한다. 플레이어 기지나 Pawn의 faction은 변경하지 않으며, 봉신 영지를 `Faction.OfPlayer`로 바꿔 일반 플레이어 기지로 만들지도 않는다.

연합 FactionDef는 바닐라 OutlanderFactionBase를 상속하고 자동 세계 생성 수와 가중치는 0이다. 게임이 무작위 연합 정착지를 추가로 생성하지 않도록 `FactionGenerator.NewGeneratedFaction`의 hidden override를 사용한 뒤, 공개 faction으로 전환하고 manager에 등록한다. 동일 Def의 기존 세력이 있으면 재사용하며 중복/멸망 세력은 임의 복구하지 않는다. 이름·설명·시민/지도자 명칭은 영한 번역을 제공하고 연합 이름은 게임의 현재 언어로 표시한다.

`UnionAdmissionLedger`에 준비/적용/취소 시각과 원 소유자·목표 세력·도시 ID를 기록한다. 실제 참조는 `UnionCityReference`가 Scribe에 저장한다. 부분 실패를 전체 성공으로 기록하거나 저장 후 도시를 다시 이동시키지 않는다. 미완료 건은 현재 소유자가 연합인지/원 소유자인지 확인해 완료/취소할 수 있고, 제삼자가 점령했거나 맵이 로딩된 상태를 임의로 덮어쓰지 않는다. 이미 적용된 도시가 나중에 정복돼도 이 초기화 코드는 자동으로 되돌리지 않는다. 적용한 건이 있으면 두 번째 초기 재편을 막으며 전부 미이동 취소로 확인된 경우에는 재검토할 수 있다.

연합의 무작위 습격과 바닐라 군사 원조 요청은 비활성화했다. 평의회 의결 없이 임의로 연합 군사를 사용하는 기능을 완성했다고 표시하지 않는다. 플레이어 가입과 공유 외교는 위 0.3.3 절에서 추가했다. NPC 소속 변경은 위 0.3.4의 제한된 별도 집행을 사용한다. **일방 독립·평의회 표결은 아직 미연결이다.** 1단계 전체가 완료된 것은 아니다. FactionDef 실제 해석/세력 생성/도시 변경/팝업/저장 복원은 코드와 빌드만 검사했고 게임을 실행하지 않았다.

### 선택형 실제 공납 전달

계약 장부에서 플레이어가 봉신인 활성 계약에 **이 계약의 실제 공납 켜기**를 선택하면 켠 시점부터 공납 일정을 시작한다. 기존 개발용 계약에 소급 청구하지 않는다. 가입/서명만으로 물품을 자동 차감하지 않는다. 고정 원금 100, 봉신 직접 배송의 운송 몫 10% 공제에 따라 회차당 인수 가치 90을 요구한다. 주기 5일·유예 1일이며 미납 자체로 자동 명예 유죄나 전쟁을 만들지 않는다.

납기 후 종주 세력 정착지 타일에 플레이어 상단을 도착시키고 납부 버튼을 누른다. 협상 가능한 플레이어 상단원과 수령지의 실제 거래가격으로 일반 소지품을 평가하며 품목별 수량·단가·총액·반환하지 않는 초과 가치를 먼저 표시한다. **전달 확정은 실제 소지품을 NPC 정착지 거래 재고로 이전한다.** 따라서 별도 가상 모델의 배송 버튼과 효과가 다르다. 현재는 직접 배송만 지원하며 방문 징수·NPC의 상납은 아직 없다.

가격은 설치된 TradeUtility.GetPricePlayerSell/GetPricePlayerBuy와 TraderKind 가격형·협상가 능력·정착지 보정·약물/축산물 보정·게임 난이도·물품 상태에 따른 바닐라 계산을 사용한다. 은은 통화 물품의 시장가로 평가한다. 거래 화면의 전역 TradeSession을 덮어쓰지 않는다. 납부 직전에 소유권·외교·상단 위치·남은 수량·단가를 다시 확인한다. 현재 일반 Item 소지품만 취급하며 Pawn·시체·축소 건물/중첩 보관물은 제외한다. 호의 통화와 작위 제한 거래는 권한 연동 전까지 거절한다. NPC 공납을 지급하려고 자원을 새로 생성하지 않는다.

`TributeLedger`는 계정·날짜별 회차·준비/확정/취소 영수증을 별도 JSON으로 저장한다. `TributePaymentLedger`는 실제 수령지·상단·운반자·물품 참조와 ThingOwner 임시 보관을 Scribe로 저장한다. 모든 선택 물품을 임시 보관한 후 수령지에 옮기고, 각 물품의 실제 목적지·수량을 확인한 다음 영수증을 확정한다. 같은 회차는 준비 중에도 재납부할 수 없다. 초과 가치는 다른 의무를 갚지 않는다. 합의 해약은 새 청구를 중단하되 이전 납기 의무와 납부 기록을 유지한다.

중단 시 완료를 입증하면 영수증을 확정하고, 그렇지 않으면 확인 가능한 물품의 반환을 시도한다. 전량 반환을 확인해야 회차 예약을 해제한다. 행방/수량을 입증할 수 없는 부분 이전은 임시 보관과 기록을 보존하며 다시 납부하도록 자동 초기화하지 않는다. 미완료 이전이 있거나 결제 장부를 복원하지 못하면 해약도 보류한다. 임의의 모드 훅 예외·외부 재고 조작에서 항상 자동 복구된다는 보장은 없다.

한 계정 최대 1,200회차, 전체 영수증 4,000개, 납부당 최대 100개 스택을 취급한다. **이는 코드/빌드 단계 구현이다. 실제 상단 전달·가격 화면 대조·실물 보존·엔진 저장 재로딩은 아직 실행하지 않았다.** 보호 임무와 일반적인 영지 소속 이전은 미완성이므로 완성 계약 모드로 Workshop에 게시하지 않는다.

### 실제 정착지 계약 장부 (추가 개발)

월드 정착지 명령 **정착지 계약 장부 / Settlement charter records**에서 실제 정착지와 세력 참조를 등록한다. 가상 전쟁 모델과 별도의 장부다. 플레이어가 봉신이 되는 제안은 NPC **세력 전체**를 종주로 기록하고, 플레이어가 종주가 되는 제안은 선택한 NPC **정착지 하나**를 봉신으로 기록한다. 모든 플레이어 기지는 하나의 플레이어 정치 ID를 공유한다. 세력의 수도 하나가 없어져도 세력이 존속하면 세력 단위 종주 참조를 임의 소멸시키지 않는다.

`CharterBook`은 고정 문안·3일 응답 기한·NPC/플레이어 개별 동의 시각·합의 해약의 개별 동의를 저장한다. NPC 동의만으로 플레이어를 종속시키지 않는다. 최종 서명과 해약 때 현재 소유권·존재·외교 자격 및 연결된 계약 영지를 재검증한다. 소유권 변경/영지 소실/적대 전환은 동작을 보류하고 기존 기록은 남긴다. 중복 주군·순환·하위 집단을 포함한 4단계 한도도 최종 체결 때 다시 검사한다.

초기 NPC 협상은 실제 현재 세력 지도자와 바닐라 우호도를 사용한다. NPC가 종주가 되려면 우호도 0, 봉신이 되려면 50, 합의 해약에는 20 이상을 요구한다. UI에 기준을 공개했다. 이는 임시 협상 정책이며 명예/장기 실적/세력 규모에 따른 협상을 완성한 것이 아니다. 해약 거절 시 요청자의 동의만 남고 계약은 유지된다. 계약 문안은 가치 100/5일·유예 1일·봉신 배송 10% 운송 공제·병력 보호 응답으로 제한된다.

GameComponent가 실제 Settlement/Faction을 Scribe 참조로, 정치 장부를 별도 버전 1 JSON으로 보관한다. 잘못된 복원은 원본 데이터를 보존하고 동작을 막는다. 코드 검사에서 동의 순서·기한·실시간 소유권 변경·중복 관측·후손 유지·변조된 저장 거절을 검증했다. **실제 게임의 저장/재로딩은 실행하지 않았다.**

**활성 기록만으로 모든 계약 효과가 집행되지는 않는다.** 실제 공납은 선택형 직접 전달만 연결했다. 초기 NPC 자유도시 배치는 별도 확정 절차이며 제한된 NPC Faction 편입은 위 0.3.4 절에서 추가했다. 보호 퀘스트·명예 변화는 미연결이다. 플레이어 공유 외교는 별도의 검토·확정 절차를 거친다. 장부 서명만으로 NPC 도시를 자동으로 연합에 옮기지 않는다. 적격 NPC 도시의 합의 해약 후 연합 편입은 별도 검토·확정으로 적용한다. 가상 모델의 영수증·전투 결과를 실제 장부로 복사하지 않는다. 장부는 한 당사자가 플레이어인 계약만 취급하며 NPC끼리의 봉신 계층 생성은 후속 작업이다.

### 독립된 가상 모델

- 안정적인 정치 주체 ID와 native faction ID 분리. 플레이어 ID는 하나로 유지하며 주민·기지의 실제 소속을 수정하지 않는다.
- 직속 계약, 순환/중복 종속 금지, 최상위 포함 4단계. 하위 집단 전체를 포함해 이동 후 깊이를 검사한다. 최상위 대외 외교 그룹을 조회한다.
- 고정 가치 공납, 5일 주기/1일 유예 예제. 봉신 배송은 운송 몫 공제, 종주 방문 징수는 추가 비용. 원금·인수 가치 분리. 기한 이후 신뢰 하락은 한 번만 적용하며 자동 명예 유죄/전쟁/해약 없음.
- 전체 모델 영수증 중복 금지, 충분한 실제 거래가치가 전달됐다는 **어댑터 입력 규약**. 미리보기 버튼은 가상 영수증일 뿐 실제 거래가격 계산/물품 인수 검증이 아니다. 초과 납부가 다른 의무를 갚지 않는다.
- NPC 대상 공격 요청, 기한, 병력 예약, 동맹 구원, 가용 병력과 원정 병력의 중복 방지, 결과/손실/명예 한 번 반영. 모델 보호 조항은 기한 내 **병력 응답**만 인정한다. 다른 지원 방식과 면책은 추후 추가한다.
- 명시한 보호 조항 미이행 → 시정 통보 → 실제 시간 기한 → 미해결이면 정당한 독립. 낮은 명예만으로 독립 불가. 양측이 수락한 시정 합의로 독립 사유를 해소할 수 있다. 독립/합의 해약 시 하위 계약·과거 공납 기록 유지, 연합 그룹으로 이동.
- NPC 패배 결과는 기록하지만 소속 이전/점령 계약을 자동 생성하지 않는다. 기존 소유권/계약을 덮어쓰지 않는다. 플레이어 기지는 추상 공격의 패배 대상에서 제외한다.
- 설정된 간격으로 번영을 간략 갱신. 날짜 기한은 턴 간격과 별개. 큰 시간 도약도 중간 기한·턴을 순서대로 처리한다.
- 명령 재생 기반 버전 1 저장: 직렬화/복원 시 같은 검증 경로. 연속 시간 갱신 압축, 미래 스키마/손상 입력 거절. 게임 Scribe에는 JSON 문자열과 시계 연결 설정을 저장한다. 복원 실패 시 원본 문자열을 보존하고 모델을 중지한다.
- 영·한 keyed 문구와 placeholder 일치 검사. 현재 게임 언어를 따르고 언어 설정을 변경하지 않는다.

초기 모델 제한: 주체 최대 200, 명령 최대 10,000, 시간 전진 호출당 최대 120일, 전체 모델 6,000일, 턴 0.25~10일(화면 1~10일). 용병단/평의회/세계 생성/개인 서약/장기 경제를 구현한 것이 아니다. 화면의 초기 정착지·병력·전투 공식·번영 수치는 시험 데이터이며 확정 밸런스가 아니다. 인구/병종·장비별 충원·별도 공납 수송 상단은 아직 없다.

## 로컬 빌드와 선택형 설치

기존 `GamePaths.props`와 .NET 10 SDK 설정 후:

```powershell
./tools/Build.ps1 -DotnetPath '<local .NET 10 SDK>/dotnet.exe'
./tools/Install-ContractsPreview.ps1 -RimWorldDir '<RimWorld directory>'
```

설치기는 게임을 실행하거나 모드 활성 설정을 변경하지 않는다. 기존 동일 package ID 설치가 있으면 `.local`에 백업한다. 직접 확인할 때 게임 모드 목록에서 **Honor.Contracts — Development Preview**를 선택한다. 로드 순서는 해당 게임 버전의 Harmony(1.6: 2.x / 1.7: 3.x) → Core 0.2.2+ → Preview. 다른 부속 모드/DLC는 필수 아님. 이후 사용자 요청 전까지 에이전트가 게임을 실행하지 않는다.

가상 모델의 향후 사용 경로(미실행): 월드맵에서 플레이어 정착지 선택 → 계약 개발 미리보기 → 모델 생성. 계약 합의 → 5일 경과 → 가상 배송 기록, 또는 가상 공격 → 구원 병력 파견 → 기한 경과 → 결과. 구원을 보내지 않았다면 시정 요구 → 합의 시정 또는 3일 대응 기간 뒤 독립. 이 가상 화면의 버튼은 모의 사건 입력이며 실제 전투 증거를 만들어 내지 않는다. 별도 정착지 계약 장부의 실물 공납은 위 설명대로 실제 소지품을 이전한다.
