# Honor Mod Series 코드 구조 및 실행 계획

기준: 2026-10-28, 공개 main 152026d와 현재 작업 트리. 이 문서는 목표 설계와 실제 구현을 구분한다. 1단계는 미완료다. 기존 CONTRACTS-DECISIONS.md의 확정 결정과 AGENTS.md의 저장/복구 조건이 우선한다.

## 제품 및 코드 경계

최종 제품은 Core, Society, Nobility, Diplomacy, Oaths, Contracts의 여섯 모드다. Contracts.Preview는 개발판이며 일곱 번째 정식 모드가 아니다. Core는 Harmony에 의존하고 각 확장은 Core를 사용한다. Nobility는 Royalty가 필요하다. Hegemony/WD2는 선택형 연동이며 단독 실행을 유지한다. API를 확인하기 전 타 모드에 정치 권한을 넘기지 않는다.

현재 소스의 Honor.Rules / Honor.Contracts.Rules는 엔진 독립 규칙과 장부, 나머지 Honor.* 프로젝트는 게임 연결이다. Honor.Contracts.Preview는 현 게임의 실제 세력/도시/폰 참조, UI와 저장을 담당한다. Mods는 기존 정식 모드, TestMods/Honor.Contracts.Preview는 계약 개발판, Tests는 규칙 검사다. 1.6/net472와 1.7/net10은 별도 산출물이며, 1.6은 설치본이 아닌 참조 DLL 기준이다.

계약 경로는 UI/사건 → 현재 실제 객체와 의사결정 권한 검토 → 복사본에서 장부·계약·공납·정치 변경 준비 → 원본/동의 재확인 → 장부 동시 교체 → 실제 세력/주민/외교 변경 → 실제 결과 기록 → 중단 시 기록을 확인해 별도 복구 순서로 유지한다. 이미 실행한 불확실 native 호출을 재실행하거나 결과를 추정하지 않는다. 플레이어 native 세력은 변경하지 않는다.

## 1단계 계약·정치·보존 — 잔여 약 35%, 7~9개 큰 작업

구현된 범위: 계약 장부/4단계 계층, 일부 연합·봉건 가입과 현 권한 확인, 제한된 하위 이전·합의 해약, 공납 마감, 일부 상실/승계·지도자 합류, 확인된 보호 거부 후 제한된 독립 및 주민이 저장되지 않은 하위 영지 이전. 각 구현은 범위와 보존 조건이 다르며 전체 완료가 아니다.

1. 주민 이전: Pawn 원본과 건강/장비/관계/신분/의료·수술·재고의 참조와 보존 증거를 유지한다. 새 개별 호출 journal에 원본 ID·source/target·호출 전 시작·실제 정상 반환 당시 의료 상태·1회 복구 소비를 저장한다. 알 수 없는 호출을 재실행하거나 변경 원인을 추정하지 않는다. 수술·포로·노예·지도자 및 로딩 지도는 각 별도의 확인과 집행이 필요하다. 현재 작업 트리의 ResidentCareJournal은 신규 일반 도시 이전의 호출·Scribe 기록·복구 경로에 연결 중이다. 정당한 독립의 주민 영지 제한은 그대로이며 완전한 저장/복구 검증과 다른 복잡 상태는 남아 있다.
2. 정치/영지 이전: 원 계약, 완전한 하위 그래프, 각 도시의 실제 소유자, 원래 이력과 별도 현재 동의를 연결한다. 변경된 원 계약과 재협상 계보, 적대 출발지, 새 전쟁의 각각 독립적인 승인과 복구가 필요하다.
3. 소실/재탈환: 실제 native 결과의 양성 증거, 기존 pending loss/정치 장부와 원 후손 범위를 결합한다. 중첩·진행 중·상위 소실, 복귀와 재계약을 처리하되 기존 계약/채무를 지우거나 옛 계약을 자동 부활하지 않는다.
4. 전체 합병: 실제 모든 정착지·주민·재고·지도자/승계·제삼자 권리·기존 계약을 범위로 묶고 원 세력의 마지막 정착지와 생명주기를 안전하게 처리한다. 제안/동의와 실제 합병을 구분한다.
5. 권한과 의결: 현 일반 지도자, 연합 평의회, 귀족/집단 의결, 계약별 대리권을 별도로 확인한다. 현재 대표 확인이 집단 동의를 대신하지 않는다.
6. 저장·복구·연동: 원본과 journal의 짝, 버전 호환, 부분 실행/예외/중단을 보존한다. Hegemony/WD2는 별도 선택형 어댑터로 권한과 소유권을 검증한 경우만 적용한다.

## 2단계 영지·공납·의무 — 잔여 약 80%, 5~7개 큰 작업

계약 조건 → 정산 주기 → 가치 평가 → 물품 인계/운송 → 영수증·채무 → 기여도·명예/신뢰의 흐름을 구현한다. 물품은 실제 거래 가치를 사용하고 정산 당시 근거를 저장한다. 기존 실물 공납 일부를 바탕으로 징수관·봉신 직접 배송과 운송 공제, NPC 영지 경제와 성장, 지연/유예/위반, 방어·노무·군사 의무, 계약별 비용과 후속 협상을 연결한다. 계약 고정 공납은 성장만으로 자동 인상하지 않는다.

## 3단계 전쟁·항복·구원 — 잔여 약 95%, 6~8개 큰 작업

세계 시계와 전쟁 상태 → 군대 편성/파견 → 일별 전투/포위 → 항복 또는 실제 점령 → 1단계 계약/소유권 → 부상·손실·구원 성과 순서로 연결한다. NPC 자동 진행과 플레이어가 직접 지휘하는 임무를 분리하고 병력 중복을 막는다. 원정대 출발·귀환·부상·장비 손실 가능성은 사전에 표시한다. 자유도시/저명예 세력 영지의 구원 후 봉신 제안은 기존 권리와 성공 증거를 확인한 별도 계약으로 처리한다. 현재 관련 규칙은 있으나 전체 세계 사건·전투·점령 연결은 미완료다.

## 4단계 명예·신뢰·영향력 — 잔여 약 90%, 5~7개 큰 작업

사건 → 개인 명예 Need 또는 세력 명예 → 계약별 신뢰/이탈 압박 → 계약 이행·관계·기여도 기반 영향력 → 체제별 의결 → 외교·분쟁 결과로 연결한다. 낮은 기여도의 영향력 상한과 명예에 의한 간접 평가를 구현한다. 선전포고/화평 건의, 강권·협상·중재·결투를 실제 정치 결과와 연결한다. 별도 개인 평판 화폐는 만들지 않는다.

## 5단계 용병단·개인 봉신·맹세 — 잔여 약 100%, 6~8개 큰 작업

용병 개인이 아닌 용병단 단위의 제안/계약/선수금/임무/최종정산/연장·해지와 소속 세력 책임을 구현한다. 병과별 조건, 숙련에 따른 성과와 실패, 부상·명시된 장비 손실, 배신/도주, 포로 구출·몸값 분담과 명예 결과를 연결한다. 노무형 자동 파견과 직접 지휘 임무를 분리한다. 기존 Oaths의 제한적 개인 맹세와 별개로 개인 봉신·서약·후계 승계의 실제 계약 및 의무를 추가한다.

## 6단계 통합·배포 — 잔여 약 70%, 4~6개 큰 작업

세계 생성/기존 저장 편입과 충돌 없는 초기화, 영한 번역/설정, 양 버전 빌드 및 패키지와 저장 호환성, 공개 모드 의존성·로드 순서·설치 문서·커버·모음집을 정리한다. Hegemony는 별도 어댑터와 충돌/권한 검사를 거친 선택 기능으로 다룬다. Contracts.Preview는 완성 전 정식 Contracts로 주장하지 않는다. GitHub 게시와 로컬 백업 설치는 검증된 범위에 한한다.

## 진행 기준

작업 묶음은 규칙 → 실제 게임 경로 → 저장/복구 → 영한 UI → 1.6/1.7 빌드·규칙·패키지 확인까지 연결돼야 기능 완료로 본다. 예외 상태를 가드만 추가하거나 테스트 수/버전만 늘려 단계를 완료로 판정하지 않는다. 퍼센트는 현재까지 남은 작업의 대략적 노력 추정이며 측정된 진척률이나 일정이 아니다. 다음 착수는 위 주민 journal의 실제 실행/보존 연결과 그 후속 소실·합병 경로다.
